## 為什麼退役:富邦年報 OCI 漏抓

`28f7fc2` 及更早的版本,富邦的**年報(H2)** OCI 桶只抓到零頭,
半年報(H1)正常。分母缺了八百多億,AC 佔比被推高 12~14pt。

以 2022H2 為例(單位:億元):

| OCI 債種 | 舊(28f7fc2) | 現行 | 財報明細表 p146 印的 |
|---|---:|---:|---|
| 公司債 | 28 | 363 | 36,255,142 千元 = 363 ✓ |
| 金融債券 | 4 | 301 | 30,096,675 千元 = 301 ✓ |
| 政府公債 | 39 | 221 | 22,138,467 千元 = 221 ✓ |
| **OCI 合計** | **405** | **1228** | printed_total 122,821,962 千元 = 1228 ✓ |

分子 AC 幾乎沒動(差 6~7,捨入等級),動的全是分母。
來源:`facts/202204_5836_AI3.json`(富邦=5836)。

### 後果:一個 bug 偽裝成兩年一循環的配置策略

因為只壞在 H2,舊表長出一個假的鋸齒:

```
        舊(壞)  現行
2020H1    70     --    H1 正常
2020H2    89     --    H2 破損 ↑
2021H1    76     73    H1 正常
2021H2    88     75    H2 破損 ↑
2022H1    77     71    H1 正常
2022H2    91     79    H2 破損 ↑
2023H1    76     76    此後兩版一致
```

**若看到富邦 AC 佔比在 88~91% 之間跳動,那張表就是這一版的產物,直接作廢。**
現行資料富邦十期落在 71~79%,是五家裡最穩定的。

另有一個中間態 `d283016`(v3 重建過程),富邦 2022H1 = 100%
(OCI 與 Trading 整個掉光),已由下一個 commit `c0e5fc1` 修掉。
那是另一個錯誤,不是同一個。
