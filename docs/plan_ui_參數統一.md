# 分析頁參數統一:一個範圍,三張圖

**一句話**:個體報表頁的參數散在六個地方,同一個概念有 2–3 個入口,結果是
**同一頁三張卡片可以在講不同範圍的數字,而畫面上沒有任何提示**。這份把「數字是誰」
全部收上去成一份全域範圍,卡片只留「怎麼畫」。

範圍:`site/index.html` 的 `page1`(個體報表)+ `page2`(個體更多)。
`page3`(合併報表)與 `page1` 共用 `make_web.py:interactive_html()`,**同步受惠,不另外做**。

---

## 裁示紀錄(2026-08-13,使用者定案)

| # | 議題 | 裁示 |
|---|---|---|
| 1 | 分類/債種/銀行/期間/口徑 | **一律全域,卡片不准偏離。** 不做「臨時偏離 + 標記」那種折衷 |
| 2 | 趨勢圖「跨行/單行」模式鈕 | **拆掉。** 單行不是跨行的一個模式,是另一個層次 —— 獨立成「單行透視」,**點銀行就地展開** |
| 3 | 圖例點擊 | **純強調/淡化,不動數字。** 不准當第三個藏起來的篩選器 |
| 4 | 全域列滾動行為 | **黏頂 + 收成一行摘要**,點開展開全部 |

第 2 點推翻了我原本的提案(把單行併進「攤開哪一軸」一顆鈕)。推翻是對的:那個
方案需要補一條「攤開分類又勾多家銀行時畫合計線」的規則,**補丁本身就是模型不對的訊號**。

## 現況盤點(2026-08-13 實測,不是估的)

可點的控制元件(不含 JS 生成的 5 顆銀行 chip):

| 區塊 | select | checkbox | 按鈕 |
|---|---|---|---|
| `page1` | 4 | 13 | 13 |
| `page2` | 0 | 0 | 4 |
| `page3`(合併,同一個產生器) | 4 | 13 | 13 |

**問題不在數量,在入口數。** 管「數字是誰」的五個概念,散在六個地方:

| 概念 | 入口數 | 在哪(id) |
|---|---|---|
| 期間 | 1 | 全域列 `B_from`/`B_to`/`G_p` |
| 哪些銀行 | **3** | 全域 `bankchips`、趨勢圖例(cross 模式→隱藏線)、趨勢圖例(single 模式→選行) |
| 哪些債種 | **2** | 全域 `inclbox`×7 + `inclQuick`、趨勢卡的 `B_b` 下拉 |
| 哪些會計分類 | **2,且無全域** | 跨行比較 `A_ccb`×3、趨勢 `B_ccb`×3(兩份互不同步) |
| 口徑 | **2** | `ix_basis`(在本期速覽卡片上,實際管整個 `page1`)、`wbasis`(數字明細自己一顆) |

管「怎麼畫」的只有 5 組,那些沒問題。

### 三個具體的錯

**① 同一頁三張卡片,三個分類範圍**

```
drawKPI   (:401)  total(p,b,"合計")  → 三分類全加,不吃任何勾選
drawA     (:469)  catSelA            → 吃 A_ccb
drawB     (:549)  catSel             → 吃 B_ccb
```

`val()` 對 `cat==="合計"` 是把三個分類直接加總([:315](../site/index.html:315)),
所以跨行比較勾「只看 AC」時,上面的 KPI 與下面的趨勢圖仍是三分類合計。
三張圖上下並排,講的是不同的東西。

**② 分子不吃勾選、分母吃**

`val(p,bk,cat,bond)` 是直接查表不看 `incl`([:313](../site/index.html:313)),
但 `B_denom()` 走 `total()` → `bondList()` → 吃 `incl`([:511](../site/index.html:511))。
全域取消勾「股票」之後,趨勢圖的 `B_b` 下拉**還是選得到股票**,畫出來的線是
「被排除的東西 ÷ 排除它之後的合計」。

**③ 說明指著看不見的東西**

`page2` 的「期間由上方工具列控制」([:668](../site/index.html:668))所在卡片顯示時,
`page1` 必然是 `hidden`([:1394](../site/index.html:1394)),工具列跟著消失。
同一頁的估值圖又用 `PH0.banks` 全部銀行([:687](../site/index.html:687)),
根本不吃全域 `bankchips` —— 全域列對 `page2` 是半通不通。

### 一個順帶(第四個實例)

`wbasis` 用 `book`/`cost`、`ix_basis` 用 `wide`/`wide_cost`,連口徑說明文字都各寫一份
([:851](../site/index.html:851) vs [:295](../site/index.html:295))。
這是 `docs` 裡記過的同一個形狀:**一道規則兩個實作**(BS 錨、GREEN 判準、`facts.DIR`
之後的第四個)。改判斷邏輯前先問「別的地方是不是也做同一件事」。

## 設計

### 一句話規則

> 全域勾選決定「有哪些數字」;卡片只決定「把哪一軸攤開」。
> **攤開的軸只顯示被勾選的成員,沒攤開的軸整個加總。**

這一句可以推出每張圖該畫什麼,不必逐張定義。全域只勾 AC 時,跨行比較攤開分類軸就
只有一段,而它跟旁邊的 KPI、下面的趨勢圖**必然**對得起來。

### 版面

全域列(黏頂,移出 `page1`,個體兩頁共用一份;合併另一份,因為期別是季度軸):

```
期間 [2020H1 – 2025H2]  當期 [2025H2]   口徑 [帳面/公允│取得成本]   新台幣(億元)
銀行 (中信)(兆豐)(國泰)(富邦)(玉山)
計入 分類 [FVTPL│FVOCI│AC]  ×  債種 [全選│只看債券│含貨幣] (公債)(公司債)(金融債)…
```

滾動後收成 `2025H2 · 5家 · 帳面 · 三分類 · 全部債種 ⌄`。
「計入」寫成 `分類 × 債種` 是刻意的 —— 讓人一眼看出這兩排合起來才是一個部位定義,
不是兩個獨立篩選器。**可見性是必要條件**:使用者原本的抱怨有一半是「滾下去就看不到
上面那個」,不解決可見性,卡片上的第二份控制還會長回來。

卡片:

| 卡片 | 留下 | 移除 |
|---|---|---|
| 本期速覽 | 無 | `ix_basis` → 全域 |
| 跨行比較 | 攤開 [債種│分類]、檢視 [金額│結構%] | `A_ccb`×3 |
| 時間趨勢 | 檢視 [金額│佔比%] | `B_mcross`/`B_msingle`、`B_ccb`×3、`B_b` |
| ↳ **單行透視**(新,點銀行展開) | 拆解 [分類│債種] | 取代舊 `renderDrill` + 舊單行模式 |
| 估值視角 | 檢視 [金額│占AC%] | 銀行改吃全域 |
| 數字明細 | 無 | `wbasis` → 全域 |

卡片層控制元件 **21 → 10**,而且剩下的 10 個**沒有一個會改變數字是誰**。
全域層 18 → 23(接管了分類與口徑)。總數 39 → 33 —— 數量不是重點,
**一個概念一個入口**才是。

### 單行透視

現在「單行」被切成兩半,兩邊都殘廢:

| | 有時間軸 | 分類拆解 | 債種拆解 |
|---|---|---|---|
| 跨行比較的「點銀行展開」([:374](../site/index.html:374)) | ✗ 只有當期 + 一條 sparkline | ✓ | ✓ |
| 趨勢圖的「單行分類」模式 | ✓ | ✓ | ✗ 只能單選一個債種 |

合成一塊,點銀行名就地展開在跨行比較底下:

```
兆豐  2025H2                                    拆解 [分類│債種]   ×
  當期結構   FVTPL ▓▓  FVOCI ▓▓▓▓▓▓  AC ▓▓▓▓▓▓▓▓▓▓▓▓
  隨時間     ── 線圖(拆分類=3條 / 拆債種=勾選的N條)──
  較上期 +xx 億 · 較去年同期 +xx 億
```

模式鈕不是被併掉,是不再需要。附帶:「點銀行」變成唯一的下鑽動作 —— 現在點銀行名
展開明細、點趨勢圖例隱藏線,同一個手勢兩種結果,那也是打架的一種。

### 底層:`SCOPE` 單一狀態源(這一段才是真正的修法)

按鈕搬家只是表面。現在會漂,是因為 `drawKPI`/`drawA`/`drawB` **各自組裝範圍**
(`total(合計)` / `catSelA` / `catSel`)。不動這層,漂移一定會回來。

```js
const SCOPE = { basis, from, to, cur, banks:Set, cats:Set, bonds:Set };
function sum(p, bk, {spreadOn, member})   // 唯一的取數入口,所有圖都走它
```

三張圖不准再自己讀 checkbox,一律 `sum()`。這也讓一致性**可以被自動測**(見驗收)。

## 驗收(必須證明會失敗)

**現在跑這四項會失敗** —— 那就是它們有效的證據。改完必須全綠。

**V1 三張卡片一致**(現在失敗)
全域只勾 AC、只勾公債,讀三個數字:本期速覽「部位最大」金額、跨行比較該行合計、
趨勢圖該行當期點值。**三者必須相等。**
現在 KPI 走三分類合計、跨行比較吃 `catSelA`,對不起來。

**V2 沒有繞過全域的路**(現在失敗)
全域取消勾「股票」→ 頁面上不該存在任何仍能選到股票的控制。
現在 `B_b` 下拉選得到,而且畫出的 % 分子不吃勾選、分母吃。

**V3 口徑單一**(現在失敗)
切「取得成本」→ 本期速覽 KPI 與數字明細表**必須同時**換口徑。
現在數字明細那顆 `wbasis` 是獨立的,不會動。

**V4 全域列永遠看得見**(現在失敗)
切到「個體更多」分頁,全域列仍在畫面上;滾到頁尾,摘要列仍在。
現在切過去整條就消失。

**V5 反向控制(這條不准全綠)**
故意讓其中一張圖不訂閱 `SCOPE` 變更(或把它的 `sum()` 換回舊的 `total(合計)`),
**V1 必須報錯**。抓不到就代表 V1 是恆真閘門,測了等於沒測。

**V6 合併頁不回歸**
`page3` 的期別選單仍是季度軸,沒有被個體的半年軸污染;V1–V4 在 `page3` 同樣通過。

前四項用瀏覽器實跑(`app.py serve` → 分析頁),V5 用注入。
`SCOPE`/`sum()` 抽出來之後,V1 可以在 jsdom 裡跑(`node_modules` 已有 jsdom,
`run_test.js` 是現成的範本),那時才進 CI。

## 這份**會改掉**一個目前刻意的行為

趨勢圖「佔比%」的分母現在**固定**是三分類合計,理由寫在
[:508–510](../site/index.html:508):「這樣兩種模式的 % 才是同一把尺」。

新規則之下,分母 = 勾選範圍的合計(全域只勾 AC 時,分母就只有 AC)。
**這不是修 bug,是照裁示 #1 的必然結果** —— 舊做法之所以需要固定分母,正是因為
分類當時是卡片層的篩選器;一旦分類升上全域,「同一把尺」自動成立,不必再寫死。

要留意的是:全域只勾 AC 時,趨勢圖每一條線的佔比都會變成 100%(分子=分母)。
那是正確且可解釋的,但沒意義。**R2 要一併處理**:攤開軸只有一個成員時,
「結構%/佔比%」鈕灰掉並附一句「目前範圍只有一個分類,結構圖恆為 100%」。

## 不做的事

- **不碰資料層。** 這份從頭到尾只動 `make_web.py` 的前端產出,`data.json`、`build.py`、
  `facts.db` 一行不動。
- **不做狀態進網址(可分享連結)。** 有價值但是另一件事,做完這份再說。
- **不重排分頁順序。** 現在是「個體報表 / 合併報表 / 個體更多」,第三個是個體卻排在
  合併後面 —— 該改,但那會動到 `#p2`/`#p3` 的既有連結,分開處理。
- **不做小倍數(五家並排小圖)。** 裁示 #2 選了「點銀行就地展開」。
