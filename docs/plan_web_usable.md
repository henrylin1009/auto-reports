# 網頁可用性計畫 —— 讓每一種失敗看得見、每一頁找得到

**目標**:`plan_web_complete.md` 讓每種卡住的狀態**有出路**;本計畫讓那些出路
**找得到、看得懂、按下去知道結果**。

**明確不是目標**:新增任何一種人工裁示的種類。十種狀態的出路都已經在了
(2026-07-30 實測 §0),本計畫一個新裁示都不加。

**判準**(都可機械驗證):
1. §3 的三條路徑各自「不開終端機、不開 Preview」走得完
2. `python3 build.py --diff` 逐字不變
3. 每一道新閘門都附一個注入測試,證明它**會失敗**(`memory/checks-must-fail`)

寫於 2026-07-30。基準線全部是當天實測。

## §0 基準線 —— 出路都在了,但三種情況下人會卡死

今天的量(2026-07-30 實測,`docs_in_scope()` 42 份):

```
done 108 · todo 4 · rejected 14 · blocked 0 · na 0 · no_data 0 · cellmeta 0 筆
```

`plan_web_complete.md` §0 那張十列盤點表**十列都有對應的網頁動作了**。
但實測走過一遍,三種情況人會卡在畫面前面:

| 症狀 | 實測證據 | 根因 |
|---|---|---|
| **找不到圖** —— 右欄那幾頁裡沒有要的表 | 右欄只有 `d.pages` 幾顆按鈕,無翻頁 / 無跳頁 / 無搜尋([workbench.js:488](../web/workbench.js)) | 「指定候選頁」用 `prompt()` 問頁碼,但**系統裡沒有地方可以找到那個頁碼** |
| **圖是裂的,不知道為什麼** | `img.naturalWidth = 0`、`alt=""`、無 `onerror`;`/page.png` 三種錯全回 500 | 頁碼超範圍 / PDF 不見 / pdfium 出事,畫面上長得一模一樣 |
| **點了沒反應** | `#/doc/nosuchdoc` 永遠停在「載入中…」 | `api()` 不看 `error`,四支 view 都沒有錯誤分支 → 例外一丟,`replaceChildren` 沒跑到 |

外加兩個**安靜的資料風險**:

- **重抄會吃掉人工列。** [fill.py:319](../fill.py) 是 `cells[key] = recs` 整格覆寫,
  沒有歷史。確認框寫的「舊版存進歷史」([workbench.js:536](../web/workbench.js))**是不實的**。
  W2 剛給的 `_src` 手改能力,被 W1 那顆「重抄」一鍵抹掉,警語一個字沒提。
- **重抄失敗看不出來。** `cell_status` 順序是 `no_data → done → blocked → rejected`
  ([core/webdata.py:153](../core/webdata.py)),已 done 的格子重抄失敗會寫 rejected
  標記檔,但 `done` 先中 → 畫面完全沒變。而 `runCell` 跑完直接 `viewDoc(reload)`,
  把那行 log 也一起洗掉了。**按下重抄 → 轉一下 → 回到原樣 → 不知道成功還是失敗。**

## §1 類似案例 —— 四個,各偷一個 pattern

| 系統 | 值得偷的 | **不要偷的** |
|---|---|---|
| [Rossum](https://knowledge-base.rossum.ai/docs/interactive-bounding-boxes-in-rossum) | **值 ↔ 位置雙向**:點值跳到位置、hover 位置看是哪個欄位 | bbox 標框。我們已裁示頁層級核對,不畫框 |
| [Docsumo](https://www.docsumo.com/platform/features/human-in-the-loop) | 左值右文件並排、佇列上用鍵盤快速鍵(A 通過 / E 編輯)一路走完 | 信心分數門檻路由。我們的閘門是算術(六道),比信心分數硬,不要退回去 |
| [Google Document AI HITL](https://cloud.google.com/document-ai/docs/hitl/quickstart)(已於 2025-01 停止服務) | 「減少每份文件的處理時間」被當成第一級指標,不是附帶效果 | labeler pool / 任務指派 / 效率分析。單人本機用不到 |
| [Correction Provenance in OCR Pipelines](https://arxiv.org/abs/2603.00884) | **curation ratchet**:記人工編輯的時戳,重跑時比對 —— 人工較新就不覆蓋 | 全欄位 ratchet。我們的單位是「列」不是「欄位」,而且「重抄」本來就常常是「我不要舊的」 |

**這四個的共同結論**:HITL 系統的成本不在「能不能改」,在「找到要改的那一處」
與「知道改完發生什麼」。我們現在正好卡在這兩件事上 —— 能改的都能改了。

## §2 我們的 case 跟它們差在哪(所以哪些做法要改形狀)

| | 商用 HITL | **我們** |
|---|---|---|
| 使用者 | 一群 labeler,不懂業務 | 一個人,懂業務、看得懂財報 |
| 定位單位 | bbox(欄位級) | **PDF 一頁**(已裁示) |
| 正確性判準 | 信心分數 | **算術**(六道,`sum(葉列) == 錨`) |
| 資料量 | 每天幾千份 | 42 份 × 3 類,長尾只剩十幾格 |

差異的結論有三條:

1. **不需要 bbox,需要「翻得到頁」。** 我們的定位單位是頁,而 `loc.texts` 已經
   持有全文([locate.py:61](../locate.py)),`locate()` 又有快取 —— 所以
   **頁面瀏覽器 + 全文搜尋幾乎是零成本**,不必新增任何抽取。
2. **不需要信心分數,需要把六道的結果講清楚。** 已 done 的格子已經會印哪一道不過
   ([workbench.js:511](../web/workbench.js)),缺的是重抄**當下**的結果。
3. **不需要 ratchet 硬擋,需要「看得到自己要丟掉什麼」+ 能還原。** 硬擋會跟
   「指定頁重抄」打架 —— 那恰好是修錯頁的正規手段。

## §3 三批 —— 順序不可換,每批獨立可驗收

### P1 —— 頁面瀏覽器(解「找不到圖」)

1. `GET /api/pagetext?doc=&q=` —— 用 `loc.texts` grep,回 `[{page, snippet}]`。
   **零新依賴、零新抽取**,`locate()` 已快取。順便回 `n_pages = len(loc.texts)`
2. 右欄改造:候選頁按鈕 **+ `←` `→` + 跳頁輸入 + 搜尋框**。搜尋框直接貼錨值
   (千分位字串)就會跳到那一頁 —— 跟 `locate.py` 找候選頁是同一招,只是這次人來下關鍵字
3. **「用這頁重抄」** 掛在當前頁旁邊:寫 `cellmeta.pages` + 重抄,一顆按鈕走完。
   `setPagesOverride()` 那兩個 `prompt()` 退場(理由改成表單上的一個輸入框)
4. `set_cellmeta` 的 `pages` 加**上界檢查**(`< n_pages`)。今天實測存 `9999` 回
   `{"saved": true}`,存完圖是裂的、重抄失敗,而訊息不會說是頁碼錯

**驗收**:拿 `202502_5836_AI3|OCI`(抄到彙總層那型)實跑 —— 從「這頁不對」到
「換頁重抄完成」,**全程不開 Preview、不打頁碼**。

### P2 —— 讓失敗看得見(解「點了沒反應」)

1. `api()` / `post()` 統一:回傳有 `error` 就在畫面頂端出一條紅字,**絕不靜止**
2. `/page.png` 三種錯分開回 4xx 帶原因;`img.onerror` 印出來
   (「這頁畫不出來:頁碼 9999 超過本檔 152 頁」)
3. **重抄結果留在畫面上**:`runCell` 完成後把 `PASS / BLOCKED / FAIL + reason`
   釘在該類卡片上,不被 `viewDoc(reload)` 洗掉
4. 已 `done` 的格子若有殘留的 blocked / rejected 標記檔,卡片上標「上次重抄失敗」
   —— `cell_status` 的**順序不動**(done 優先是對的),只是把被蓋掉的事實顯示出來

**驗收(注入測試,`memory/checks-must-fail`)**:手動塞一個壞頁碼、砍掉一份
`pdf_cache/*.pdf`、對一格灌一個必失敗的重抄 —— 三次都要在畫面上讀得到原因,
不是裂圖、不是「載入中…」。

### P3 —— 重抄不再無聲吃掉人工列

1. 重抄前把舊 `recs` 存 `work/history/{doc}__{cls}/{ts}.json`(落地在 `fill.py`
   寫入前那一行,不是在 server 層 —— CLI 走同一條路)
2. 確認框**說實話**:若該格有 `_src` 列,**列出那幾列的名字**,要打字確認
3. 重抄完若真的丟掉了人工列,卡片上出一顆「還原上一版」

**驗收**:對一格手改一列 → 重抄 → 確認框有列出那一列 → 重抄後能還原回去。
`build.py --diff` 對純機器格子仍逐字不變。

## §5 不做的事

- **不畫 bbox**。頁層級核對是已裁示的,Rossum 那套框在我們這裡是純成本
- **不加信心分數門檻**。我們的閘門是算術,比信心分數硬
- **不做 ratchet 硬擋**。它會跟「指定頁重抄」打架 —— 那正是修錯頁的正規手段
- **不動六道檢查的內容**,也不動 `cell_status` 的判斷順序
- **不動 `locate.py` 的候選頁演算法**。P1 是給人用的第二條路,不是改機器那條
- **不碰自動化率**(仍是另一份計畫的事)

## §6 要你裁示的一件事

**重抄前的「打字確認」會不會太煩?**
傾向:只有**該格真的有 `_src` 列**時才要求打字,純機器格子照舊一個 confirm。
理由:煩的閘門會被繞過,而純機器格子重抄本來就沒有東西會遺失。
