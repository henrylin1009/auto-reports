# 工作台設計（2026-07-29）

> 取代 7/29 上午那版（照管線階段排畫面的工程視角）。

## 裁示紀錄（2026-07-29，使用者定案）

| # | 議題 | 裁示 |
|---|---|---|
| 1 | 範圍 | **只做 2023 起。** ≤2022 那 31 份定位不到的不管——死因是四大表被掃描成影像、文字層沒有科目代碼,修不了 locator,也不在需求裡 |
| 2 | 介面形態 | **模式二:本機服務。** 不是靜態頁、不是匯出補丁、不是 chat |
| 3 | 技術 | **Streamlit**（`pip install streamlit` + `streamlit run`),不手刻 `http.server` |
| 4 | 靜態總覽頁 | **先不做。** 等真的嫌「看進度還要開服務」再加 |
| 5 | PDF 定位粒度 | **頁層級**,不做 bounding box 座標高亮 |
| 6 | 分區鍵 | **年 × 銀行 × 報表代碼**,代碼集合從資料推導,不准寫死列舉 |
| 7 | 現行工作台 | `core/workbench.py` 那六個管線分頁**廢掉**,由本設計取代 |

**為什麼是模式二**:需求裡有「對著圖填數字」和「換桶」,那是寫入。
靜態頁寫不回去（資料在瀏覽器記憶體裡,沒有管道進 `facts/`);
匯出補丁每次要手動搬檔案。剩下就只有本機服務。

「看」與「寫」分開是業界通例——`dbt docs`、Great Expectations Data Docs、
覆蓋率報告都是跑完產出的唯讀靜態頁;複核類工作（Label Studio、Streamlit、
Gradio、Voilà）一律起服務。**沒有一家用純靜態頁做複核。**

## 一、範圍與現況

2023+ 共 **42 份 PDF、126 格**（格 = `{期別}_{銀行}_{代碼}|{類別}`）：

| 狀態 | 數量 |
|---|---|
| 抄完了 | 35 |
| 抄完卡在分類（等人按桶） | 1 |
| 定位得到、還沒抄 | 90 |
| **定位失敗** | **0** |

2023 起錨 100% 讀得到（`locate.py` 檔頭實測基準:「錨讀不到 96,全部 ≤2022,
2023+ 為 0」)。所以這個範圍內**沒有定位問題**,工作台不必處理它。

唯一的缺口是季報:Q1/Q3 只有 5841 AI1 有檔,其他五家沒下載。要不要納入未定,
先不納入;真要補是 `resolve.py` 的事,不是工作台的事。

## 二、狀態機

```
待抄 ──【抄列台】人或 agent 讀表──▶ transcribe.verify 六道檢查
                                          │
                                  ┌───────┴───────┐
                                  ▼               ▼
                                 過了          分桶對不到
                                                  │
                                            【裁示台】按鈕選桶
                                                  │
                                                完成
```

兩個卡點、兩個畫面。**不准有「靜靜跳過」的狀態**——現在 `fill.py._pick_next()`
對沒候選頁的格子是直接 `continue`,在 2023+ 範圍內雖然不會發生,總覽仍要能顯示
「這格為什麼不在待辦裡」。

## 三、技術選型：~~Streamlit~~ → 手刻網站（2026-07-29 傍晚推翻）

> **裁示變更**：Streamlit 做出來之後使用者看了實物，判定「格式很醜」，
> 要求換成一般網站。**這是看過實物才做得出的判斷，不是原本推理錯了**——
> 下面那段成本分析仍然成立（膠水層確實約 150 行），只是漏算了一項：
> 版面被框架決定，而版面正是這次要的東西。
>
> 現況：`server.py`（標準庫 `http.server`，約 150 行）+ `web/workbench.html`
> + `web/workbench.js`。取數邏輯抽在 `core/webdata.py`，由 `test_webdata.py`
> 盯著（17 條），UI 再換一次也不必重驗數字。
>
> ⚠️ 前端放 `web/` 不放 `site/`——`site/` 是 `make_web.py` 的產出目錄，
> 在 .gitignore 裡，手寫原始碼擺進去會靜靜地不進版控。（差點踩到。）

### 以下為原始（已推翻）的選型論證，保留備查

手刻 `http.server` 的話,每加一個畫面就要先寫 `/api/xxx` 回 JSON、前端 `fetch`
再渲染。今天做的 demo(`demo_server.py` + `workbench.js`)約 400 行,一半是那層膠水。

```
既有模組（facts / locate / transcribe / buckets / fill / core.*）
        ↑ 直接 import,不經 HTTP
   workbench_app.py   ← 只寫畫面
        ↓ streamlit run
   localhost:8501
```

代價:
- 多一個 `pip install streamlit`。這打破「本機零安裝」——但那條原則是為了
  **mentor 雙擊執行 `app.py`**,`app.py` 保持零依賴不動;複核台是給作者自己用的。
- 每次互動整支腳本重跑,狀態用 `st.session_state`。
- 鍵盤快捷鍵不好做,先不做。

今天手刻的 `site/workbench.html` / `workbench.js` **不丟**——版面(格子矩陣、
左表右頁、頁面導覽)照抄進 Streamlit。丟的只有 `demo_server.py`。

## 四、三個畫面

### 1. 總覽（首頁）

期別（列，新的在上）× `銀行 + 報表代碼`（欄），一格一份檔。

**欄位印代碼原字串，不做代碼→中文的翻譯。** 今天為此踩了兩次坑:先漏了 AI1
（把兩份檔畫成一格,另一份無聲消失）,修完又漏了 AI2。**代碼集合從資料推導,
不准寫死列舉。**

格子顯示 `已抄/可抄`,有卡住的加 ⚠。空白 = 那期沒這份檔。

篩選:年度 / 銀行 / 代碼 / 狀態（只看待抄、只看卡住）。
篩完可以「重新判定這 N 份」——**文案不准寫「重新抓財報」**,因為 `jobs.py` 的
`ingest` step 目前是 `print(...)` 佔位,按下去不會去抓 PDF。

點格子 → 進對應畫面。

### 2. 裁示台（分桶對不到的）

左邊該格全部列、右邊證據頁圖、下方桶按鈕。

- 桶按鈕從 `config.BUCKETS` 產生（10 個），**不是自由輸入框**。
  現行 `core/workbench.py` 的 `<input name=mapping placeholder="桶名">` 就是這次要廢的。
- 同名批次套用:先列出那 N 處讓人逐一看過再送,**不盲套**。
- 送出 → `core.review.dispose_confirm()` → `ratify.new_rule()` + `ratify_rule()`。

### 3. 抄列台（90 格待抄的）

左邊填表、右邊該頁的圖。這是最早提的需求:「找不到就給我那一頁的截圖放旁邊,讓我去填」。

- 右邊:`pypdfium2` render 的頁面圖（實測 `page.render(scale=1.6).to_pil()` 可跑,
  1190×1684,零新依賴）。頁面導覽列出這一格所有證據頁。
- 左邊:`st.data_editor` 表格輸入,欄位是 `rows` 的 name/cols/group。
  上方常駐顯示 BS 錨值與抄列規矩摘要。
- 送出 → 走 `fill.py submit`,`transcribe.verify()` 六道檢查照跑。
  **不准為了 UI 方便新增任何接受分支。**
- 另一顆:「交給 agent 抄」→ 產出 `/fill` 工單。實際執行要 Claude Code CLI
  （這台機器沒裝),先定好接口,裝了就通。**一次一格,不做「按下去自動跑完 90 格」。**

## 五、三個必須修的資料層問題

**① 兩套人工佇列並存（最先修）**
`core/decision_store.py` 讀 `review/queue.jsonl`（**檔案不存在**),
`fill.py` 寫 `work/proposals.jsonl` + `work/blocked/`（**8 筆提案、1 格卡住**)。
現行工作台看的是空的那套,所以顯示「待審 0」而實際有東西卡著。
**畫面全綠、實際卡住——比缺功能危險。**

**② `source_page` 是單一整數，但證據會跨頁**
`202504_5847_AI3|OCI` 的 `source_kind` 寫著「附註(兩層,主 p41 + 子附註 (一)p41/(二)p42)」
——p.42 只存在於那行自由文字裡,`source_page` 只有 41,頁面導覽因此列不出 p.42。
改成 `source_pages: [41, 42]`。

**③ 分區鍵是「年 × 銀行 × 代碼」**
同一家同一期可以有 AI1/AI3 並存（`202504_5841` 就是)。代碼集合從資料推導。

## 六、順序

| 階段 | 做什麼 | 為什麼排這裡 |
|---|---|---|
| **S0** | 修①佇列合流 | 假綠燈,最危險 |
| **S1** | 總覽頁（唯讀） | 先看得到全貌 |
| **S2** | 裁示台 | 現在就有 1 格在等,也是最早提的需求 |
| **S3** | 抄列台 | 90 格的出口 |
| **S4** | 修②③ + 分區重跑 | 正確性與效能,不擋前面 |

S0→S1 之後就有東西可用。S2/S3 各自獨立,做完一個多一個出口,隨時可停。

## 七、不做

- **≤2022 的 31 份**（已裁示:只做新版）
- **bounding box 座標高亮**（已裁示:頁層級就好）
- **agent 自動跑完全部待抄**。一次一格,人按一次跑一格。
- **`site/index.html`**（對外報表頁,給 mentor 看的,跟工作台是兩個東西）
- **chat / widget 當主介面**。今天試過:適合例外處理,不適合量產複核。保留當補充。
