## 三、四個地基判斷

1. **這不是 pipeline,是「一次性轉錄 + 永久帳本」。** 89 份 PDF 永不改變;一格人工確認過就凍結。
   核心資料結構是只增不改的帳本,不是可重跑的作業圖。每輪只碰未確認的格 → 單調收斂。
2. **稀缺的是人的注意力,不是 token。** 10.5M tokens 是幾小時額度;360 格人工複核是好幾週。
   每個決策用同一把尺量:**能不能減少必須親眼看的格數。**
3. **唯一會殺死專案的是無聲的錯。** 空白格不可怕。`661,445,489` 那種看起來合理的錯才可怕。
   第二把尺:**能不能把靜默的錯變成大聲的錯。**
4. **冗餘不要自己發明,財報已經印給你了。** `check_rowsum` 有效是因為財報另外印了小計;
   跨文件互證有效是因為每個數字被兩份 PDF 各印一次(78/81)。

## 四、架構

```
L0 語料   89 份 PDF(內容雜湊固定) + 每頁文字 + 每頁 PNG(可重算的衍生物)
             ↓
L1 讀     一份文件 = 一次 LLM 呼叫。抽文字 → 去中文字間空白 → 整份進 context
          一次回這份的所有格子:3 類 × 帳面/成本 × 所有印出的期別
          每個數字帶:值 / 引用頁 / 財報印出的小計 / BS 科目金額
          掃描圖不是另一條管線 —— 同一支 reader、同一份 prompt、同一個 schema,
          只把輸入從頁文字換成頁影像
             ↓
L2 證     七道 witness,純函數,零 LLM。每道都是「同一數字的兩個獨立來源必須相等」
             ↓
L3 分流   GREEN / RED / GREY
             ↓
L4 帳本   append-only。ratified 的格子凍結,永不重讀
             ↓
L5 呈現   複核台(只給 RED + GREY 抽樣) / 比較表(每個數字帶 witness 計數)
```

## 五、七道 Witness

| | 檢查 | 獨立性來源 | 抓什麼 |
|---|---|---|---|
| W1 | Σrows == 財報印出的小計 | 財報另外印了一次 | 抄錯某一列 |
| W2 | 小計 == 資產負債表科目 | 跨報表 | 抄錯整張表 |
| W3 | 數字字串出現在引用頁 | 機械 grep(`webdata.pagetext` 已有) | 引錯頁 |
| W4 | 本期的前期欄 == 前一份的當期欄 | **另一份 PDF、另一次呼叫** | 已驗證 78/81 |
| W5 | LLM 分的桶 == taxonomy 查表 | 跨方法(80 條 CONFIRMED 降級當證人) | 分桶錯 |
| W6 | 帳面 − 成本 == 評價調整 + 備抵 | 算術恆等式 | **口徑被替換** |
| W7 | DeepSeek 抽的值 == Claude 抽的值 | 不同模型/tokenizer/訓練 | 最硬的一道($1.85) |

### 鐵則:`no_witness` 必須由程式強制,不准信模型自報

held-out 那跑證明了這條的必要性:BS 那頁是**掃描圖空白**,模型在散文裡誠實說
「無法直接對照」,但 JSON 欄位寫 `check_anchor: {"status":"OK","diff":0}`。
**只吃 JSON 就會被騙。**

→ schema 必須有 `no_witness` 這個值;L2 要程式覆寫:BS 頁抽不出文字 →
`check_anchor` 一律改成 `no_witness`,不管模型說什麼。該格落進 GREY。

## 六、分流:用 witness 計數,不用 confidence score

分數會引來閾值,閾值會引來調參,調參就是 v3 那 14 個靜默 bug 的溫床。

```
GREEN  ≥2 道獨立 witness 通過,0 道失敗   → 直通,人不用看
RED    ≥1 道失敗                         → 進複核台,並排顯示打架的兩個來源 + 差額
GREY   0 道失敗,但 witness < 2(孤證)     → 抽樣看,不是全看
```

GREY 是 v3 沒有的狀態。v3 只有「過/不過」,所以黃金集才會得出
「誠實率 100% 是假的 —— 管線把所有格子都收下」。

## 八、刻意不做

- 不做 locate / 候選頁 —— 整份都在 context 裡
- 不做擴頁預算與重試政策 —— 沒有東西可以擴
- 不做分桶決策引擎 —— LLM 決定,taxonomy 當證人
- 不做作業圖與指紋快取 —— 帳本就是快取,ratified = 完成
- 不做切片 / 分塊 / 重疊視窗 —— 去空白之後沒有一份超 context。
  重疊視窗尤其無用:BS(p.8)與明細表(p.150)差 140 頁,任何 overlap 都搭不起這座橋,
  而富邦那份 BS 是掃描圖能繞道成功,**靠的正是三處同在一個 context**
- 不分半年報/年報兩條路 —— schema 用 `null` 表達「這份沒有」
- 不用 confidence score —— 用 witness 計數

## 十、風險清單

- **n=2。** 兩份都 100%,但 prompt v1-v3 是在第一份上診斷後寫的(fit to sample);
  只有第二份是真 held-out。要繼續累積分母。
- **掃描圖只驗證了「不捏造」,沒驗證「讀得到」。** 該份 13 頁無文字、主要報表 p.7-12 全是圖,
  模型繞道成功;但真正需要從影像讀值的那批(2018-2020,10 份封面全空)完全沒測。
- **W3 對掃描頁必然失效**(grep 永遠落空)→ 一律 `no_witness`,不准當通過。
- **W4 遇到財報重編會誤報** —— 但那正是該知道的事,是特性不是缺陷。
- **驗收基準本身可能有錯。** `facts/` 的 `source_page` 是 v3 寫的,而黃金集證明 v3 有 14 個真 bug。
  切片評測那 11 個「漏抓」裡至少 2 個疑似基準錯(頁面內容根本不是目標表)。
