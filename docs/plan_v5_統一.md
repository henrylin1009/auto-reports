## 一、目標架構

**一個引擎、一個事實庫、一條發布路徑、四個頁面。**

```
PDF ──► v4.reader ──► v4/raw/{doc}.json        整份丟,不切片
                          │
                          ▼
                    v4.witness (純函數,零 LLM)   W1 Σrows=小計 · W2 小計=BS錨 · W3 成本
                          │
                          ▼
                    v4.buckets  ← buckets.py / wide.py 原封不動共用
                          │      閘門:Σ桶 ≠ 小計 或 有列對不到桶 → RED,不准靜靜掉列
                          ▼
                    v4.ledger  ── GREEN 直通 / RED·GREY 進待辦 ── 人在網頁看 → ratify
                          │
                          ▼
                    build.py ──► data.json ──► make_web.py ──► site/ ──► GitHub Pages
```

三條鐵則不變:
1. **發布的數字一定有算術證明**,證不了就是 `null`,不准猜。
2. **witness 一律程式重算**,不信模型自報(富邦那次 BS 是空白掃描圖、模型照樣填 OK)。
3. **分流看 witness 計數,不看信心分數** —— 分數會引來閾值,閾值會引來調參。

`facts/` 的處置:**凍結,不刪、不再寫入**,降級成 v4 的回歸測試基準(見 P2)。

## 二、執行計畫

### P0 止血(約半天)—— 先讓現在的東西不會爆、不會騙人

| # | 做什麼 | 驗收 |
|---|---|---|
| P0-1 | 修 `build.py:157` 的 `None` 格崩潰(`table.get(cell) or {}` 後要寫回) | `build.py --diff` 跑得完並印出差異 |
| P0-2 | 拔掉 `cell_status()` 與 `doc_detail()` 裡的 v4 hook(0.3 節那兩段) | 矩陣 `/api/overview` < 0.3s;沒有任何格會顯示假的 `checks.ok=true` |
| P0-3 | `facts/` 40 檔 + `anchors/` 進 git,單獨一個 commit | `git status` 乾淨 |
| P0-4 | v4 三個孤兒路由掛進 nav(暫時的,P3 會重做) | 從首頁點得到 |

> P0-2 拔掉之後,文件頁的 v4 區塊會消失 —— 這是對的:在 P1 把 v4 接上分桶與發布路徑
> 之前,它本來就不該被畫成「已完成」。

### P1 讓 v4 成為完整引擎(核心,約 3–4 個工作天)

**P1-1 修 reader 的 schema:rows 要分 `group` / `name` 兩欄**

實測 4 份 v4/raw 的 137 個列名,用現成的 `buckets.py` 只對得到 96 個(70%)。
對不到的 41 個裡,絕大多數是**名字帶了段落前綴**:

```
債務工具-公司債券            → 應該是 group="債務工具"  name="公司債券"
權益工具投資－未上市（櫃）股票  → group="權益工具投資"   name="未上市（櫃）股票"
強制透過損益按公允價值衡量之金融資產－商業本票
```

另外 9 個是 `小計` / `合計` / `淨額` —— 這些根本不該當 rows,應該進 `printed_subtotal`。

改 prompt + 加一層純函數 normalizer(遇到 `-` / `－` 就拆),兩邊都要,
因為模型會忘,normalizer 是保險絲。

**P1-2 接上分桶與口徑,共用既有邏輯不長第二套**

寫一支 **adapter**:v4 的 `book` / `cost` → `wide.view()` 認得的 recs 形狀
(`{"class", "rows":[{"name","group","cols":{col:amount}}], "total_col"}`),
然後 `buckets.py` / `wide.py` / `closure.py` **一行都不改**直接接上。

閘門(新增,而且必須證明它會失敗):
- `wide.view().unknown` 非空 → **RED**(有列對不到桶 = 那筆錢憑空消失)
- `Σ七桶 + Σside ≠ printed_subtotal` → **RED**
- 這兩條要各寫一個「注入錯誤後必須變紅」的測試,沒有這個測試不算做完

**P1-3 `build.py` 改讀 ledger**

`rebuild_v3()` → `rebuild_v4()`:`v4.ledger.load_all()` → adapter → `wide.cell()` → verdict。
`bridge_v3.cell_of()` 直接沿用(key 格式相同)。**只採用 `RATIFIED` 與 `GREEN`**,
RED/GREY 一律回退快照,理由照舊寫進 manifest。
「v3 的 null 不會抹掉 v2 的數字」這條鐵則原封不動搬過來。

**P1-4 跑批**

89 份 × 實測 2:53–3:43 ≈ **5 小時**。已量到:去空白後最大一份是
`202302_5836_AI3` 195,266 字 ≈ 122k token,**全部 89 份都在 200k context 內,不需要切片**。
分批背景跑,每批完成寫進度檔,可中斷續跑。

### P2 遷移驗證(約 1 天)—— 砍 v3 之前唯一誠實的證據

**這一步是「全面轉 v4」這個決定的安全帶,不能跳。**

`facts/` 有 156 格已經過六道檢查的真值。v4 跑完之後逐格逐桶比對:

| 結果 | 處置 |
|---|---|
| 七桶完全相同 | v4 該格直接標 GREEN(v3 當成第三道 witness) |
| 有任何一桶不同 | **兩邊都進待辦**,人翻原始頁裁決,並記錄是誰錯 |
| v3 有 / v4 沒有 | 進待辦,查是漏讀還是 v3 抄錯 |

產出一份 `docs/v3_v4_對照.md`。**不一致率 > 5% 就停下來重新評估「全面轉 v4」這個決定** ——
現在的證據只有 n=2(國泰年報 + 富邦半年報 held-out),兩份都 24/24,
但那是兩份,不是八十九份。

### P3 2020–2022 納入(約 1 天,但有已量到的天花板)

已量到的事實,先講清楚會拿到什麼:

| 年 | 份數 | 全份有文字層 | BS 頁讀得到(能對錨) |
|---|---|---|---|
| 2020 | 10 | 8 | 2 |
| 2021 | 11 | 11 | 3 |
| 2022 | 10 | 10 | 5 |
| 2023–2025 | 42 | 42 | 30 |

- **2 份純影像**(`202002_5835`、`202002_5847`)v4 也讀不了,只能標「無資料」,不是 0。
- **2020–2022 的半年報 BS 頁多半是掃描圖** → W2(小計=BS錨)失效 → 那些格只剩 W1 一道
  witness → 依規則是 **GREY(孤證)**,不會自動 GREEN,要人抽樣看。這是誠實的代價,
  不要為了讓畫面變綠而放寬分流規則。
- `data.json` 的 2020 那幾個 `null` 格要在 P0-1 一起處理成正常空 dict。

矩陣的年份範圍從 `CUTOFF_YEAR = 2023` 改成 2020,前台不再有「後台點不到」的數字。

### P4 網頁重做(約 2–3 個工作天)—— 這是「更直覺」的部分

**動線收斂成一句話:看矩陣 → 點一格 → 左邊逐列、右邊原始頁 → 改 → 按發布。**

頁面從 8 個路由砍到 **3 個 + 1 條狀態列**:

| 頁 | 是什麼 | 取代掉 |
|---|---|---|
| **分析** | 前台本體(iframe) | 不變 |
| **資料** | 期別 × 銀行矩陣,一格一份財報 | 不變 |
| **文件** | 核對台:左列右圖,改資料的唯一地方 | 不變 |
| **待辦** | RED 不一致 + GREY 孤證 + 分桶待裁示,一條清單 | `#/queue` `#/buckets` `#/v4review` `#/v4run` 四頁合一 |

具體改動,按「痛的程度」排:

1. **永遠在的發布狀態列** —— 「ledger 有 N 格比 data.json 新」+ 一顆「發布」。
   發布完給 site/ 連結。現在完全沒有這個訊號,你不知道網站是不是舊的。
2. **即時對帳條** —— 核對畫面頂端固定一條:`Σ列 452,141,000 · 錨 452,141,000 · 差 0`,
   改任何一格數字**當場重算**,綠色才准發布。現在改完要重載才在小字看到一行。
3. **點下去要立刻有反應** —— 矩陣點格先畫骨架再等資料(P0-2 之後 API < 0.3s,但骨架照做)。
4. **分桶就地改** —— 每列右邊的桶名點一下就換,不必跳到另一頁拖曳。
   拖曳版留在待辦頁做批次改判。
5. **56 處 `alert`/`prompt`/`confirm` 全換掉** —— 改成 inline 表單 + 右下角 toast。
   「填理由」這種必填欄位用 `prompt()` 是目前最卡的互動。
6. **一顆按鈕只做一件事,而且說清楚** —— 「重抄」要寫明:用哪個模型、會覆蓋什麼、
   大約多久。現在按下去只有一行跑馬燈。
7. **狀態顏色只留三種** —— 已核可(綠)/ 待你看(黃)/ 沒資料(灰)。
   現在 done·todo·blocked·rejected·no_data·na 六種 + v4 的 GREEN·RED·GREY·RATIFIED 四種,
   十種狀態畫在同一張表上。
8. **鍵盤** —— `j/k` 換列(已有)、`Enter` 編輯、`Esc` 取消、`⌘S` 存。

### P5 收尾(約 1 天)

- `locate.py` / `bs_anchor.py` / `buckets.py` / `wide.py` / `closure.py` **留著**,v4 在用。
