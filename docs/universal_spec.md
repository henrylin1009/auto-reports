# 零設定通用抽取機 — 規格(地基)

目標:**做一個東西,任何一家、任何一年、沒看過的新格式,丟進去都能出數字。**
不為任何一家寫規則。唯一「設定」是「你要什麼輸出」(桶 + 對帳),寫一次、全共用。

對照業界(template-free / schema-driven + 80/20 + hierarchical validation):
- 數字由座標精準抽取,**LLM 只做語意對應**(品名 → 桶)
- 一律過**對帳驗證**才收;不過 → N/A → 人工待審清單

設定與規則全部集中在 [`schema.py`](../schema.py)。

---

## 流程(五段,零 per-bank 邏輯)

```
PDF ──①抽字──▶ 文字/座標 ──②定位──▶ 候選表頁
        │                                │
        └──(乾淨表 pdfplumber 免費;字元湯座標重組)
                                         ▼
                              ③讀值+對桶(LLM 按 schema)
                                         ▼
                              ④取當期欄、分「入桶 / 只對帳」
                                         ▼
                              ⑤對帳:桶+對帳項 ≈ 錨?
                                  過→收(億元)   不過→N/A→人工
```

## 六條硬規則(此版已固化進 schema.py)

| # | 規則 | 為什麼 | schema.py 對應 |
|---|---|---|---|
| 1 | **找頁不猜關鍵字**:用分類標題撈所有候選頁,LLM 判斷哪張是明細表;排除敘述句 | 靠猜關鍵字換家就崩 | `TITLES` / `NARRATIVE_EXCLUDE` / `BOUNDARY` |
| 2 | **雙錨**:內錨=表『整則總合計』(非債券小計);外錨=資產負債表對應科目,**三類一律「必須相等」**(統一無分支)。前提:OCI 連權益工具一起讀(→股票桶)、AC 吸收減損/備抵,故整則合計三類皆=資產負債表 | 防抓錯同名子表(自洽假過);OCI股票桶順帶補齊 | `balance_sheet_anchor()` / `ANCHOR_BS` / `RECONCILE_ONLY_KW`(含減損備抵) |
| 3 | **對桶語意寫死、共用**:LLM 只在 schema 查不到的新品名才臨場判斷 | 每次臨場判會不一致 | `SYNONYMS` / `bucket_of()` |
| 4 | **入桶 vs 只對帳有界線**:衍生/評價/避險算對帳、不入桶 | 否則湊不到總數 or 汙染桶 | `RECONCILE_ONLY_KW` / `is_reconcile_only()` |
| 4 | **取衡量基礎欄**:依 IFRS 衡量基礎選欄(Trading/OCI=公允價值,AC=攤銷後成本);資產負債表以衡量基礎入帳,故「合計==資產負債表」自動確認選對欄 | AC 取市價會錯(應取成本);寫死欄位/欄名易崩 | `MEASURE` |
| 4b | **釘死來源表**(確定可重現,非per-bank):OCI/AC→主附註(五家都按桶列且為公允價值/帳面);Trading→明細表優先(兆豐主附註股票列是『取得成本』13,361,875,公允價值18,008,316只在明細表公允價值欄,且兆豐無資產負債表外錨可擋此錯→Trading必讀明細表)。H1無明細表才退主附註 | LLM各家挑不同表→口徑不齊;Trading讀主附註會取到成本 | `SOURCE` |
| 5 | **永遠取當期欄**:兩欄報表只取當期;當期破折號=0 | 取去年欄會「假過對帳」(最陰險) | `TAKE_COLUMN` / `DASH_AS_NIL` |
| 6 | **對帳當保險絲**:桶+對帳項 ≈ 錨才收 | 擋 LLM 幻覺/抓錯表 | `reconciles()` |

## 驗證(不能只信對帳)

對帳只保證「表內自洽」,不保證「口徑一致」。故盲測結果**逐格比對現有 `data.json` / oracle**,
差異拉出來人看——這是抓「抓到另一張同名表 / 口徑漂移」的唯一辦法。
