## 0. 一句話:改變了什麼

**舊路線:** Python 解析表格結構(認標題、認小計、認欄序)→ LLM 只負責分桶。
**新路線:** **Python 只負責「找到頁」與「驗收」,讀表全交給 agent。**

轉折點是一次實測:我寫的結構解析器在 2023+ 得 61/123,而 62 個失敗**全落在 12 個(銀行×分類)組合、每組正好 6 期** —— 看起來像「再補 12 條規則就滿分」。
使用者否決:那是在重造死規則解析器。→ 見 `memory/feedback-no-format-hardcoding`。

連帶結論:**魔術常數也是打版**,只是換個維度。任何憑單一樣本挑的容差/門檻/視窗,
動工前必須先跑全語料敏感度掃描。

### 2.1 定位為什麼是通用解

零版型知識 —— **不認標題、不認小計、不認欄序**,只問「哪一頁印著這個數字」。
候選頁中位 2 頁、最多 4 頁,總字數中位 1,751。**agent 讀純文字,不讀圖。**

副產品:同一份年報裡同一個合計會出現 2~4 次(BS / 附註 / 明細表)。
實測國泰 2021:OCI 在 p6 / p36 / p133,AC 在 p6 / p37 / p92 / p134。
→ **天然的雙來源交叉驗證,而且是免費的。**

### 2.2 三層分離:事實 / 判斷 / 視圖

```
S4 agent 抄列  → rows        事實,不含任何判斷,只存表上印的原名
S6 同義詞對照  → buckets.yaml 判斷,一次性,人審,進 git
S8 Python 聚合 → wide         視圖,純查表,隨時可重算
```

**rows 只存原名,分桶是查表當下算的,不寫進 JSON。** 改表直接重算,不必重讀 PDF。

### 2.3 rows 的形狀(**本次才定下來,先前討論漏了**)

先前一路都寫成 `(原名, 金額)`。**那是錯的,會讓 `wide_cost` 再也做不出來。**

年報明細表一列有多欄(面額 / 利率 / 取得成本 / 公允價值 / 帳面金額 / 累計減損),
半年報附註只有其中一部分。所以:

```json
{"name": "公司債", "cols": {"取得成本": 96457734, "備抵損失": 30661, "公允價值總額": 95908835}}
```

- **欄名存原文**,不做正規化 —— 正規化屬於 S6 判斷層,不能污染事實層。
- 「哪一欄是帳面、哪一欄是成本」的對應**寫在 buckets.yaml 旁邊**,跟同義詞同一個生命週期。
- 缺的欄就不放 key。**不准補 0** —— `null`(未揭露)與 `0` 是不同的事實。

## 3. 分桶:不是分類判斷,是跨行同義詞對照

年報明細表與半年報附註**顆粒度相同,兩邊都已經歸好類了**:
`國庫券 / 商業本票 / 政府公債 / 公司債 / 金融債 / 可轉讓定存單 / 股票投資 / 基金受益憑證`。

所以不存在「把明細分到桶裡」這件事,只有「兆豐寫政府債券、國泰寫政府公債,要對到同一個名字」。規模小一個量級:

1. **機械正規化**(去 `（附註十一）`、統一全半形破折號括號)—— 零判斷
2. **同義詞對照** —— 約 20~30 組
3. **真的要人決定的** —— 個位數

**同義詞表可以自動長出來**:同一份文件裡**金額相同、名字不同 → 定義上就是同義詞**。
自動配對產生候選清單,人只要審。

> ⚠️ **但這只在年報成立** —— 需要一份文件裡有 2 份以上的表述,而半年報只有附註一份。
> → **表從年報長,套用到半年報。** 若半年報出現年報沒有的名目,只能靠人審補。

**順序是「先抄列、後分類」。** 從「掃候選頁」建表是錯的:實測會得到 212 種名目,
金額前十名有 6 個是鄰表(`保證及承諾` / `－房貸` / `外幣放款`)或結構列(`投資` / `總帳面金額` / `淨額`)。

### 3.1 已知需要真人決定的

- `國外機構發行債券`(玉山,15 次,金額大)—— 字面分不出公司債 / 金融債
- **衍生性金融商品**(`遠期外匯合約` / `利率交換合約` / `選擇權`)—— Trading 明細表包含它們,
  但網站現有 7 個 wide 桶沒有對應欄位。**這是真的分類決定,不是同義詞問題。**

## 4. 驗收:四道檢查(**要誠實標明哪幾道實際存在**)

1. 附註列相加 == 印出合計
2. 明細表列相加 == 印出合計
3. **兩張表逐列金額互相對得上**
4. 合計 == BS 錨

**恆等式改成 `sum(所有葉列) == 印出合計`,與分桶脫鉤。**
舊式 `sum(桶)+衍生+調整==總額` 把分桶錯與抄錯綁在同一條式子裡互相掩護。

**小計 / 合計是結構列,不進和。** 中信 2023H1 OCI 實測:把 `小計` 當資料列 → 剛好 2 倍
(債務工具 197,244,969 + 權益工具 12,089,466 = 209,334,435)。**這就是先前 20 格「多算」的成因。**

### 4.0 R2 實測修正(2026-07-26,抄了 3 格之後)

**a. 第 3 道必須按「金額」比,不能按「名字」比。**
國泰 2024 OCI:附註寫 `金融債`、明細表寫 `金融債券`,金額同為 29,073,073。
按名字比會把**每一組同義詞都誤判成失敗**。而那些名字差異正是 S6 要的同義詞候選 ——
**第 3 道檢查與同義詞產生器是同一個機制,不是兩件事。**

**b. 檢查是三值的:通過 / 不適用 / 失敗。**
「不適用」不准畫成綠燈 —— 那就是 §1 D1 的恆真閘門借屍還魂。

**c. 第 3 道在年報也不是都有。** 口徑或顆粒度不同就不適用(見 §4.3 兆豐)。
國泰有、兆豐沒有。**「年報一定有雙來源交叉驗證」是錯的。**

### 4.3 口徑(basis)必須是資料,不是假設 —— **R2 抓到的最大問題**

兆豐 2024 年報 Trading,兩頁各自都自證通過,**卻互相對不上**。原因不是抄錯:

```
附註(p31)   非衍生列 = 取得成本,衍生工具 = 公允價值,再用一列「評價調整」補到公允
明細表(p125) 逐列雙欄:取得成本 + 公允價值總額

實證:明細表非衍生公允 49,748,539 − 非衍生成本 44,512,606 = 5,235,933 = 附註的「評價調整」
      明細表六項衍生的公允價值之和              = 9,082,587 = 附註的「衍生工具」
```

→ 附註上的 `公司債券 21,684,995` **是成本,不是帳面**(帳面在明細表是 22,284,807)。

**殺傷力在 S8:** 若 bridge 把附註的列彙總進 `wide`(帳面),**兆豐會被系統性低估,
而總額檢查照樣全綠** —— 總額是對的,錯的是每一桶。這正是 `oracle-basis-mismatch` 記憶,現在有機制。

**所以:**
1. 每筆 record 必須宣告 `basis`;**漏宣告就照樣逐列比、照樣失敗**(不准拿「不適用」當逃生門)。
2. **S8 只准同口徑彙總。** 文件只給成本時,該格逐桶的帳面值是 `null`,
   **不准把成本當帳面填進去,也不准補 0。**

### 4.4 兆豐 H1 的逐桶帳面金額**在文件裡不存在**(硬限制,不是 bug)

半年報同結構(2024H1 / 2023H1 皆已驗),且**沒有明細表可以救**。
所以兆豐 H1 只有「逐桶成本 + 一整筆評價調整」(2024H1 = 6,710,394)。
→ 這就是 `config.BUCKETS` 裡那個一直沒說清楚的**「調整項」桶**的來歷。

### 4.5 口徑橋接檢查該放在分桶**之後**

「明細表非衍生公允 − 成本 == 附註評價調整」是一道很強的檢查,但它需要「衍生 vs 非衍生」的分組。
試過用機械規則(有沒有取得成本欄)代替 → **差 13,553**(選擇權有成本卻是衍生)。
→ 那個分組是**分桶判斷**,所以這道檢查屬於 S6 之後,不屬於 S5。

### 4.1 三個不准講錯的地方

- **第 4 道不是獨立檢查。** 用錨值定位之後,「合計==錨」定義上必然成立。真正獨立的是 1、2、3。
- **半年報只有第 1、4 道。** 沒有明細表 → 沒有第 2、3 道。
  **H1 的驗證強度天生弱於 H2,不准假裝四道都在。**
- **恆等式驗不到「配對」。** 它檢查金額欄相加,而**欄的和與名字怎麼配對無關**。
  名字整排錯位、金額照樣加得對。→ 要驗配對只能靠第 3 道。

### 4.2 拒收

沿用 P1.4b 設計,不改:拒收單位 = **一份文件的一個類別**;`null` 與 `review` 不准並存;
**不准為了讓某格變綠而新增接受分支**(§0.1 第 3 條)。

## 6. 分欄剝離:已結案,不做任何處理

「名稱一整塊、數字一整塊」,Python 無法機械配對。實測:

| | |
|---|---|
| 至少一頁候選剝離的格 | 4 / 169 |
| **所有候選頁都剝離的格** | **2 / 169**(同一份的兩個版本 = 實質 1 格) |

**架構自帶冗餘**:錨值 grep 每格回 2~4 頁,而剝離是**逐頁**的渲染意外
(`202104_5835` 連號三頁:p132 剝離、p133/p134 完全正常)→ 一半自動被吸收。

**座標重建已否決,三個數字:**

- 固定 y 容差是硬編碼:字高 4.1~10.1,311 頁裡 253 頁結果會隨容差在 3~8 之間改變。
- 自適應版(容差 = k × 該頁中位字高)最好 26/123,**直接按行讀是 61/123**。
- **「讓 agent 自己調 k」也不行,收益是 0**:任一 k 的聯集只有 28,而
  **座標救到、基準救不到的 = 0 格** —— 座標版過的格是基準的**真子集**。

**而且剝離頁還會缺資料:** `202104_5835` p132 的衍生性金融商品四列,
公允價值在文字層裡**根本不存在**(只有面額),差額 37,120,397。
→ **任何純文字方法都救不了。要嘛看圖,要嘛拒收。**

> 若哪天真要救:給 agent **原始字元座標**或**直接看該頁的圖**,都比讓它調 k 好 ——
> 前兩者零參數,調參則是對驗收指標擬合。
