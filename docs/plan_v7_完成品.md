## 零、體檢 —— 以下每一條都是 2026-08-12 實跑量到的

### 0.2 doc id 已經人看得懂(2026-08-12 完成)

### 0.3 ⚠️ v6 R3 的「視覺化脫鉤」解錯了問題 —— 這是這份計畫最重要的一條

v6 花了 2–3 天做 `viz_generic.py`(通用視覺化層,不認得任何銀行名字),
驗收判準是「換一份 `schema.yaml`(例如上市公司研發費用)照樣畫得出來」。

**但使用者要的通用性是「多幾家銀行」,不是「換題目」。** 於是:

- `viz_generic.py` **162 行,零樣式、零互動、裸 HTML 表格** —— 技術上通用,
  產品上沒有臉,而且**沒有任何人會用它**(`/generic.html` 是「試畫」連結)。
- 它解決的是使用者沒有的問題,卻沒有解決使用者有的問題。

**而且「make_web.py 焊死這個題目」這個診斷本身已經過期。** 實測:

```
make_web.py:14   BANKS = D["banks"]           ← 讀 data.json,不是寫死
make_web.py:937  re.sub("const BANKHUE={...}", 由 config.BANK_COLORS 注入)
make_web.py:939  re.sub("const VC={...}",      由 config.BANK_COLORS 注入)
```

寫在 JS 字串裡的五家色票是**佔位符,產出時被正則換成設定值**。
v6 文件說的「BANKHUE 五家色票寫在 JS 字串裡」是看原始碼得到的結論,
**沒有看產出**。

**結論:通用視覺化層(162 行)應該退場,不是把它做漂亮。**
維持它要付的代價是第三條渲染路徑 + 一份假 schema 的回歸測試,
換到的是一個沒人用的功能。

### 0.4 加第 6 家銀行,實際會壞在哪 —— 比想像中窄很多

活程式碼(排除 `archive/` `legacy/` `scratchpad/` `test_`)裡寫死五家清單的地方

## 一、如果今天從零開始蓋,會蓋成什麼樣

> 這一節刻意不參考現有結構,先想對的形狀,再去對照差多少。

### 1.1 它其實是一個「有審核流程的資料集編輯器」

不是「報表產生器」。核心迴圈是:

```
一份 PDF  →  機器讀出候選數字  →  人看著原始頁確認  →  確認過的進事實庫  →  重算分析
                    ↑                                        ↓
                    └────────── 對不上就退回、標明為什麼 ──────┘
```

**這個迴圈已經完整存在而且會動。** 從零蓋也會蓋成這樣。

### 1.2 一個前端,三個面向,共用一套元件

從零蓋不會寫四份渲染邏輯。會先做一套元件:

| 元件 | 三個面向怎麼用它 |
|---|---|
| **網格**(期別 × 銀行,含完整度著色) | 核對台:點進去核對 · 分析頁:唯讀總覽 |
| **逐桶表**(分類 × 桶 × 口徑) | 核對台:就地改桶 · 分析頁:唯讀明細 |
| **時間序列** | 分析頁:趨勢 · 模擬器:情境軌跡 |
| **缺漏標示** | 三處共用同一套視覺語言(現在三套) |

差別只在**互動能力**(可編輯 vs 唯讀),不在渲染。

### 1.3 「加一家銀行」是一條有 UI 的路徑,不是改設定檔

從零蓋會把它做成:網頁上輸入代碼與名字 → 上傳(或抓)PDF → 自動跑完 → 出現在網格上。
**現在缺的只有第一步**(其餘都會動)。

### 1.4 設定的邊界:銀行清單是資料,不是程式碼

`config.BANKS` 現在是 Python 字典 —— 改它要編輯原始碼。
從零蓋會讓它是一張表(或 `banks.yaml`),網頁能改。

### 1.5 不會蓋的:題目無關的通用層

從零蓋、知道目標是銀行財報,**不會蓋 `viz_generic.py`**。
把銀行清單/期別/桶當資料傳進去,已經足夠應付「多幾家銀行、未來期別」。

## 二、鐵律

v6 的九條全部沿用(不放寬檢查、不打版型、不手塞同義詞、不補 0、衍生物不落地、
人工蓋過機器、不長第二條路徑、一次一條 session、「兩種原因一種結果」是 bug)。

v7 新增三條,對應 §0.3 / §0.5 / §0.6:

10. **不為想像中的需求蓋抽象。** 通用層、外掛機制、schema 驅動 —— 除非**現在就有
    第二個真實使用者**,否則不蓋。v6 R3 花 2–3 天蓋了一個沒人用的通用層,
    這條就是為它寫的。
11. **同一種視覺元素不准有第二套實作。** 網格/時間序列/缺漏標示各只准一份。
    新面向要用,就去用那一份;不合用就改那一份。
12. **給別人的東西不准是紅的。** 測試全綠才叫完成品。修不動的測試要嘛修、
    要嘛刪掉並寫明為什麼 —— **不准留著當背景雜訊**,那會讓真的紅燈看不見。
