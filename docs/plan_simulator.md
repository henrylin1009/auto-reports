# 配置模擬器 —— 構思與計劃

> 目標：把 `docs/ac_oci_發現彙整.md` 的靜態測量，變成一台**可以轉旋鈕的機器**。
> 輸入 = 配置決策 + 環境衝擊 + 制度規則；輸出 = 資本、股利、浮虧、以及**誰先被咬**。
>
> 口徑一律 **個體 AI3**、基準時點 **2025H2**，與報告一致。

---

## 0. 為什麼模擬器是對的下一步（不是因為好玩）

報告裡有三個地方是**相關係數永遠做不出來**的，而它們剛好都是模擬能處理的：

| 卡住的地方 | 為什麼相關性做不出來 | 模擬怎麼解 |
|---|---|---|
| §7 久期 | 三種算法全失效；水準法錯、衝擊法被幣別打敗 | **不估，改掃**。久期當座標軸，看結論在合理區間內會不會翻 |
| n=5 | 五家、五個群集，任何檢定都不會顯著 | 模擬不需要 n。它問的是「這家銀行如果換一種配置會怎樣」，是**反事實**不是**推論** |
| §5.4 鏈條斷點 | 法規盯的是「其他權益整箱」，股票會蓋掉債券浮虧 | **交互作用**只能模擬。股債同時動的效果，單變數相關看不到 |

而且報告裡已經出現兩次**排序翻轉**（§5.2b 富邦帳面第 2 安全 → §6.3 市值下唯一跌破 11%）。
排序翻轉 = 非線性 = 只有掃參數才看得見。這是模擬器最有價值的產出。

**一句話定位**：這不是預測工具，是**把三個做不出來的東西轉成參數空間**的工具。

## 1. 別人怎麼做（借什麼、不借什麼）

| 框架 | 做法 | 借 | 不借 |
|---|---|---|---|
| **BCBS 368 IRRBB** | 標準化利率衝擊（平行上下、陡峭、扁平、短端上下），**逐幣別**分別衝擊，靜態資產負債表，輸出 ΔEVE / ΔNII | ★★★ **逐幣別衝擊** —— 這正是 §7 打敗我們的東西，把它變成制度化的做法；**靜態表假設** | 它的 ΔEVE 用全表現金流，我們只有債券部位 |
| **Fed CCAR / DFAST** | 宏觀情境（20+ 變數路徑）→ 損失模型 → 9 季 CET1 路徑 | 「情境是**路徑**不是單一數字」；輸出看**最低點**不是期末 | 信用損失模型（沒資料，硬做就是編） |
| **EBA / ECB 壓力測試** | 靜態表 + 3 年 + 逐行揭露、橫向可比 | 「橫向可比」的紀律：五家用同一套參數跑，差異只能來自部位 | 三年動態展望 |
| **Jiang, Matvos, Piskorski & Seru (2023)**《Monetary Tightening and U.S. Bank Fragility》 | 把 HTM 按市值重估 → 「市值資本」；第二層加未保險存款擠兌 | ★★★ 第一層我們**已經做了**（§6.3）。它證明這條路是主流方法，不是野路子 | 第二層擠兌 —— 台灣存放比長期 < 80%、存款過剩，擠兌不是這裡的機制 |
| **IMF Čihák《Introduction to Applied Stress Testing》** | 單銀行資產負債表、Excel、逐層加假設 | ★★ **先做恆等層再加定價層**的教學結構 | — |
| **金管會銀行壓力測試** | 輕微／嚴重情境（GDP、失業、房價、利率），半年一次 | 官方情境數值可以當預設按鈕（「金管會嚴重情境」） | 它是合規練習，不回答配置問題 |

### 我們獨有、別人沒做的第二層

Jiang et al. 的第二層是「未保險存款 → 擠兌」。
**台灣版的第二層是「其他權益轉負 → 特別盈餘公積 → 凍結股利」**，
因為台灣**無 AOCI 豁免 + 特別盈餘公積 + 配發率 ~100%**（§5.1）。
英文文獻沒有這條通道；報告 §5.2 已量到**配息線比資本線早 5~17 倍到**。

→ **模擬器的核心賣點就是把這條通道做成第二層。**

## 2. 架構：兩層，嚴格分開

```
┌─ 定價層【假】 ──────────────────────────────────────────┐
│  (Δy_TWD, Δy_USD, 久期, 幣別權重, 信用價差, 股票報酬)      │
│                    ↓  一階近似                            │
│  ΔP(c,k) = −P(c,k) × [ Σ_ccy w_ccy·D(c,k)·Δy_ccy         │
│                        + D_spread(c,k)·Δs_k ]            │
│  股票：ΔP = P × r_eq                                      │
└──────────────────────┬───────────────────────────────────┘
                       ↓ 每一格的價格變動（35 格 × 5 家）
┌─ 恆等層【恆】 ──────────────────────────────────────────┐
│  OCI 債券 ΔP  → 其他權益 → CET1 **全額扣**（台灣無豁免）   │
│  AC   ΔP     → 帳面完全不動；只進「市值 CET1」影子帳       │
│  Trading ΔP  → 損益 → 未分配盈餘 → CET1                   │
│  其他權益 < 0 → 提特別盈餘公積 = |負數| → 凍結等額盈餘     │
│  可分配 = 未分配 + 淨利 − 法定30% − 特別公積提列           │
│  現金股利 = 可分配 × 配發率（§50 上限開關）                │
│  CET1' = CET1 + 淨利 − 股利 + ΔOCI ;  RWA' = RWA + ΔRWA   │
└──────────────────────────────────────────────────────────┘
```

**為什麼一定要分兩層**：恆等層零假設，錯了就是程式 bug；定價層全是假設，每個都要掃。
輸出必須標明哪部分是【恆】哪部分依賴假設的久期 —— 沿用報告的證據等級標記。

**AC 的三種視角**（開關，不是三個模型）：
① 會計視角：AC 不動（現實）② 經濟視角：AC 按市值（§6.3）③ 被迫賣：實現虧損 + 整桶 tainting。

### 狀態向量（每家銀行，t0 = 2025H2）

| 欄位 | 來源 | 現況 |
|---|---|---|
| `P(c,k)` 公允 35 格、`Q(c,k)` 成本 35 格 | `data.json` wide / wide_cost | ✅ 齊 |
| `FV(AC), BV(AC)` → AC 隱藏浮虧 | `capital.json.fair_value` | ✅ 25/25（富邦 2023 缺，不影響 t0） |
| `CET1, T1, T2, RWA, rwa_credit/op/mkt` | `capital.json.capital` | ⚠️ **兆豐 2025 缺**（見 §7） |
| 淨利、股本、法定／特別公積、未分配、其他權益 | `capital.json.equity` | ⚠️ **只有 13 個 bank-year，兆豐 0 格** |
| 幣別權重 `w_USD(c)` | **沒有任何資料** | ⚠️ 先當參數，見 §7 的資料獵捕 |
| 久期 `D(c)` | 只有中信 OCI 4.7y、兆豐 OCI 1.5y（IFRS 7） | ⚠️ 參數 + 兩個釘子 |

## 3. 參數：哪幾個重要（按「會不會翻轉結論」排）

### Tier 1 —— 會翻轉結論，必須做成滑桿

| # | 參數 | 為什麼是第一級 | 建議掃描範圍 |
|---|---|---|---|
| 1 | **久期 × Δy 的乘積** | 一階效果就是這個乘積。中信 OCI 2,865 億 × D=4.7 × 100bp = 135 億 = 到 11% 緩衝（259 億）的 **52%** —— 一碼半就吃掉一半墊子 | D ∈ [1, 6] y；Δy ∈ [−200, +400] bp |
| 2 | **幣別權重 w_USD** | §7 已證明這是五家差異的最大來源：2022 台幣 +62.5bp vs 美元 +425bp，**差 6.8 倍**。同樣的久期，幣別不同結果差好幾倍 | w_USD ∈ [0, 1]，逐桶可分 |
| 3 | **AC / OCI / Trading 配置 α** | 使用者最想玩的旋鈕。**而且它有一個一眼看懂的教學效果**：拉 α → 帳面 CET1 線會動，市值 CET1 線**完全不動**（恆等）。一張圖講完「AC 是會計遮蔽不是經濟避險」 | α_AC ∈ [0, 1] |
| 4 | **股票報酬 r_eq** | §5.4 的斷點就在這。兆豐 OCI 股票 458 億，跌 30% = −137 億 ≈ 債券跌 4.2% —— **同數量級**。股票能單獨決定箱子是正是負，也就決定凍不凍結 | r_eq ∈ [−40%, +30%]；另加 ρ(股,債) 兩點：同向／反向 |

### Tier 2 —— 量會變，排序不太翻

5. **信用價差 Δs**（分券種）—— 五家全部在加資產基礎（§4.5），這是尾部；但沒有 LGD 資料，只能純情境，**不准假裝有估計**。
6. **淨利 / PPNR 衝擊** —— 決定「幾年賺得回來」與可分配盈餘。
7. **RWA 成長** —— 分母效應；跌價會讓信用 RWA 跟著降（所以報告的③是保守值）。
8. **曲線形狀**（陡峭／扁平）—— 只有在 D(AC) ≠ D(OCI) 時才有意義。
9. **週轉率 / 再投資比例** —— 只在多期模擬有意義；它是 §7「券老」效應的來源。

### Tier 3 —— 制度開關（反事實實驗，最有論文價值）

10. **AOCI 豁免 on/off** —— 一鍵切成美國制度。直接回答「台灣不給豁免，代價是多少」。
11. **目標 CET1 線** —— 9%（法定）／11%（D-SIB 實務）／12.5%，玉山非 D-SIB 用 7%。
12. **特別盈餘公積規則** —— 全額提列 vs 比例；解凍後還不還給股東。
13. **AC 可否處分**（tainting）—— 量化「賣不得」的代價。
14. **銀行法 §50 15% 上限** —— 預設關閉（§第二項免除，體質正常不會咬到），但要能打開驗。

> ⚠️ 沿用 [[feedback-no-format-hardcoding]]：**上面每一個常數都必須是參數，不准寫死在函式裡**。
> 容差、門檻、預設久期，全部進 config，並且要有敏感度掃描。

## 4. 輸出：哪幾個數字重要

### 一級輸出（可排名、可上表）

| # | 輸出 | 為什麼 |
|---|---|---|
| 1 | **臨界衝擊 bp**（分幣別）：撞到 11% 線 / 配息線 / 法定 9% 各需要幾 bp | ★ **最好的單一輸出**。它把不同規模的銀行放到同一把尺上，而且可以直接對照 2022 實際值（台幣 62.5bp / 美元 425bp）—— 讀者立刻知道「這距離 2022 有多遠」 |
| 2 | **先撞哪條線 + 兩條線的距離倍數** | 報告 §5.2 的 5~17 倍。模擬要能顯示這個倍數在什麼參數下會反過來 |
| 3 | **帳面 CET1 vs 市值 CET1 雙軌** | §6.3 的排序顛倒就在這兩軌的差 |
| 4 | **凍結額 → 可分配盈餘 → 現金股利**（億元 + 元/股 + 配發率） | 台灣獨有的第二層，也是最有感的輸出 |
| 5 | **排序翻轉** | 帳面 ⇄ 市值 一按就重排（§6.3）。**不另做熱圖**，見 §11.4 |

### 二級輸出

浮虧率（AC / OCI / 總，對得上 §6.1）、每跌 1% 吃掉幾 % 淨利（§6.5）、
幾年賺得回來（浮虧 ÷ 淨利）、其他權益餘額路徑、RWA 與資本各項的瀑布分解。

畫成什麼樣見 **§11**：一頁三張圖（臨界線圖 / 瀑布 / 盈餘去向），旋鈕在上、拖了就動。

## 5. 識別性：久期問題的正確處理方式

**一階近似下，久期與 Δy 只以乘積出現 → 單一年度的資料永遠分不開。**
2022 給我們 5 條方程式（每家一個實際跌幅），未知數是每家 (D, w_USD) 共 10 個 → **欠定**。§7 卡在這裡。

**但模擬器把它變成超定問題**：

```
方程式   5 家 × 4 年(2022~2025，每年 (Δy_TWD, Δy_USD) 組合不同) = 20 條
未知數   5 家 × (D_OCI, w_USD, 週轉率) = 15 個
外部釘子 中信 OCI 4.7y、兆豐 OCI 1.5y（IFRS 7 揭露）= 2 個硬約束
符號約束 D > 0、0 ≤ w ≤ 1
```

→ **20 條對 15 個未知數，加 2 個釘子，可解，而且殘差本身就是假設的檢驗。**

關鍵前提有兩個，必須先講清楚再算：
- **要用 Δ浮虧率，不能用水準** —— 水準含累計效應（§7 的第一個坑）。
- **週轉污染是真的**（6~34%），所以週轉率必須進未知數，不能假設 0。

**退路**：若殘差過大 or 解不穩定（留一年法會翻），就**退回純掃描模式** —— 不宣稱估出久期，
只宣稱「在 D ∈ [1,6] 的整個區間內，結論 X 都成立 / 在 D > 3.5 之後就翻掉」。
**退路也是合格產出**，而且比硬估一個數字誠實。

## 6. 驗收閘門（必須證明會失敗）

沿用 [[checks-must-fail]] —— 每道閘門都要配一個**注入錯誤必須紅燈**的測試。

| 閘門 | 內容 | 注入什麼必須失敗 |
|---|---|---|
| **G0 零衝擊** | 所有 Δ = 0 → 輸出逐格等於 `data.json` / `capital.json` 基準 | 把任一格 baseline 改掉 1 元 |
| **G1 回測 2022** ★ | 以 2021H2 起點，餵 2022 實際 Δy 與股票報酬 → 模擬 OCI 浮虧要對上 §6.1 的五個實際值 | 幣別權重全設 0（全台幣）→ 兆豐必須對不上 |
| **G2 α 恆等** | α_AC = 1（全放 AC）→ 帳面衝擊必須 = 0，**且市值衝擊完全不變** | 若市值也跟著變 = 影子帳寫錯 |
| **G3 單調性** | 把某家 CET1 調低 1pt → 它的臨界 bp 必須下降 | 若不變 = 閘門恆真 |
| **G4 口徑** | 個體 / 合併不可混；千元 ↔ 億元換算；D-SIB 門檻分家（玉山非 D-SIB） | 餵合併 CET1 進個體算式必須報錯 |
| **G5 加總** | 各桶 + 各券種加總 == 報表總額；CET1' 的瀑布各項相加 == 期末 | — |
| **G7 官方對帳** ★ | `capital.json` 每一格 CET1/T1/BIS == 銀行局 `bis_e.xls` 同期同家（§7.0，現況 25/25） | 把任一格改 0.01pt → 必須紅燈 |
| **G8 口徑開關不是裝飾** ★ | 整體↔揭露 切換，軸①② 至少各要有一年**發生排序翻轉**；否則這顆鈕降級成註腳，不佔版面最上面 | 把揭露端的公式改成跟整體端一樣 → 必須紅燈 |
| **G9 單邊分桶** | 軸②揭露端用到的 OCI 券種格，公允與成本**不可以一邊有值一邊 0** | 把任一格的成本改成 0 → 必須紅燈（否則會生出假浮虧，富邦 2022H2 −11.41 vs 真值 −2.15） |

**G1 是這台模擬器唯一能證明自己不是玩具的機會。** 它同時是久期反解的校準步驟。
如果 G1 過不了，先不要往下做 UI。

## 7. 資料來源與缺口

### 7.0 官方統計：資本適足率的外部真值 ★ 2026-08-06 查證

**銀行局／金管會逐家季報，口徑經驗證是「個體」，與債券資料同基礎。**

```
bis_e.xls   https://www.fsc.gov.tw/webdowndoc?file=/stat/bis_e.xls
            逐家 × 46 季(103Q4 → 115Q1) × 3 個比率(CET1 / 第一類 / 資本適足)
            38 家本國銀行(含純網銀)、「查簽數」、表尾有平均與註解
bis.xls     https://www.fsc.gov.tw/webdowndoc?file=/stat/bis.xls
            逐家 × 2007Q1 → 今、只有 BIS 總比率，歷史更長
頁面        https://www.banking.gov.tw/ch/home.jsp?id=595&parentpath=0,590
            &mcustomize=bstatistics_view.jsp&serno=201105120015
```

**口徑驗證（決定性）**：拿 114Q4~110Q4 五家 CET1 對 `capital.json`，**25 格逐格對上「個體」欄，零例外**：

```
季別       中信    兆豐    國泰    富邦    玉山     ← 官方 bis_e.xls
114Q4    11.91   14.16   12.67   12.07   11.99
113Q4    11.96   12.53   11.73   12.02   11.63
112Q4    11.38   13.25   12.02   12.71   11.61
111Q4    11.76   12.39   11.02   11.74   10.07
110Q4    14.97   12.97   12.56   12.26   10.32
                 ↕ 逐格相同
2025 個體 11.91    —     12.67   12.07   11.99   ← capital.json（年報抄讀）
2025 合併 11.14    —     11.72   10.64   11.58   ← 明顯不同,可排除
```

三個收穫：

1. **兆豐 2025 = 14.16% 確認為真**，而且**就是報告 §5.2b 那個我在專案裡追不到來源的數字**。
   缺口補上，且不必重跑 `capital_auto.py`。
2. **`capital_auto.py` 的年報抄讀被外部獨立驗證** —— 官方統計與年報是兩條完全獨立的路，
   25 格全對。這比原本的五道內部對帳硬得多（有外部真值了）。
3. 官方註 4 印「38 家均已達到 108 年最低資本要求（7%、8.5%、10.5%）」，
   **獨立確認 CET1 法定基準是 7%**；報告的「D-SIB 9%」= 7% + D-SIB 2%，與 §5.2b 一致。

**⚠️ 但只能用一半：官方檔案只有比率，沒有 RWA 金額、沒有 CET1 金額。**
模擬器的核心式子 `可跌(億) = (CET1% − 11%) × RWA` 需要 **RWA 絕對值**，
比率無論多準都反推不出來。**所以年報抄讀不能停**，官方統計的定位是：

```
✅ 外部驗收真值（每一格抄讀都該對一次）      ✅ 補比率缺格（兆豐 2025 已補）
✅ 頻率從「年」升到「季」(46 季)             ✅ 擴樣本到 38 家的比率那一半
❌ 取代年報 —— 沒有金額                     ❌ 提供 RWA 拆解(信用/作業/市場)
```

→ 建議加 `capital_official.py`：抓這兩個檔、轉成 `capital_official.json`、
逐格比對 `capital.json`，不合就紅燈。**這道對帳直接變成 G7。**

### 7.0b 第三支柱揭露：金額在這裡 ★★ 2026-08-06 查證

官方統計缺的 RWA 金額，在**銀行自己網站的法定揭露**裡 —— 而且比年報好用。

```
法源   「本國銀行資本適足性與風險管理相關資訊應揭露事項」(巴塞爾第三支柱市場紀律)
       每家本國銀行**必須**在網站設「資本適足性與風險管理專區」→ 五家都有,不是特例
形式   制式附表一~六十二,連「填表說明」都印在頁上 → **五家同表同表號,不必寫 parser**
頻率   **半年**(表上自己印的),且每份含「當期 + 前一年度同期」→ 天然的跨份重疊驗證
```

**【附表三】資本適足比率** 就是模擬器要的全部：

```
自有資本      普通股權益第一類/其他第一類/第二類/自有資本合計
加權風險性資產  信用 / 作業 / 市場 / 合計        ← ★ 官方統計沒有的金額
比率          普通股權益 / 第一類 / 資本適足
槓桿比率      第一類資本淨額 / 暴險總額 / 槓桿比率   ← ★ 全新變數
欄位          本行 | 合併 並列(四欄)              ← 個體/合併一次拿到,不會混
單位          新臺幣千元
```

**驗證（兩家、兩條獨立路徑）**
- 兆豐揭露頁：六道對帳全過（CET1/RWA、自有資本加總、BIS、信用+作業+市場、第一類、槓桿）；
  113 年欄 = CET1 3,290 億 / RWA 26,260 億，**與 `capital.json` 年報抄讀逐格相同**。
  114 年欄 = **14.16%**，補上缺格。
- 富邦 `fubon_11412.pdf`（173 頁，**文字層零空白頁**）：本行 CET1 2,903.5 億 /
  RWA 24,065 億 / 12.07%、合併 10.64%，**與 `capital.json` 個體與合併欄皆逐格相同**。

## 9. 已知陷阱（都在報告裡付過學費）

1. **恆等式改寫不是發現**（§5.3）—— 模擬器很容易大量生產這種東西。
   任何輸出如果只是輸入的換寫（例：「每碼吃淨利」vs「AC 佔比」），必須標【恆】，**不准當結果報**。
2. **水準 ≠ 變動**（§7）—— 回測一律用 Δ。
3. **個體／合併不可混**（踩過兩次）—— 11% 線法規上套在合併，債券資料是個體。
   模擬器要把口徑印在每一張輸出的表頭。
4. **全體同向的東西橫斷面測不出來**（§4.6）—— 模擬也一樣。
   五家一起跌的情境，看的是絕對水準不是排序。
5. **不要為想像中的困難預先加機制**（[[feedback-measure-before-concluding]]）——
   P0 先做恆等層，不要一開始就寫凸性、選擇權、行為反應。
6. **兆豐的 AC 公允價值揭露排除貨幣市場**，其他四家是全額（§11 的 ⚠）。並列比較會用到兩把尺。

## 11. 呈現與互動設計（定案 2026-08-06）

### 11.0 兩個視圖，一套引擎

```
視圖 A  定位空間   四根軸、選軸即選圖         回答「這五家是誰」
視圖 B  壓力模擬   臨界線圖 / 瀑布 / 盈餘去向   回答「衝擊之後會怎樣」

共用:頂部定義選單、狀態向量、恆等引擎、BANK_COLORS
連結:在 A 點選一家銀行 → B 自動切到那家
```

**不合併成一張圖。**試過在腦中合併：四根軸裡只有 RWA/CET1 與報酬會隨衝擊移動，
非公債佔比與利率敏感度基本不動——衝擊的故事在 CET1 與股利上，不在這四根軸上。
硬合併會讓兩邊都變鈍。

### 11.1 技術：手刻，掛進既有工作台

```
server.py 開頭:「為什麼不是 Streamlit:試過,版面是框架決定的,改不動。
                手刻的代價是這一層約 150 行膠水,換到的是版面完全自己控制。」
```

`web/sim.html` + `web/sim.js`，`<link>` 進 `web/tokens.css`（全站唯一設定源），
銀行色用 `config.BANK_COLORS`，掛在 `server.py` 當新分頁。零框架、零 CDN。

**★ 新網頁還是加進舊的？答案是「新的一頁，掛進舊的工作台」** —— 三件事分清楚：

```
① 既有的本機工作台   server.py + web/workbench.html      複核抄列用的,不動它
② 這台模擬器         web/sim.html + web/sim.js  ← 新增   nav 加一個分頁連過去
                     server.py 加一條 /api/sim,只轉 JSON,取數一律在 sim/
③ GitHub Pages 成果頁 site/index.html(make_web.py 產出)  第二階段才內嵌
```

- **不是獨立的網站**：共用 `server.py`、`tokens.css`、`BANK_COLORS`、nav 列。
- **不是塞進 workbench.html**：那頁是抄列複核的工具，兩件事混在一頁只會互相擠。
  ⚠️ 也**不要寫進 `site/`** —— 那是 `make_web.py` 的產出目錄且在 .gitignore 裡，
  手寫原始碼放進去會靜靜地不進版控（`server.py` 開頭已經寫過這個坑）。
- **第二階段**才把引擎（不到 150 行）內嵌進 `site/index.html`，讓 GitHub Pages 上
  的成果頁本身能玩。屆時 G6 雙引擎對帳（§11.8）才會用到。

**便宜之處**：計算是純算術，狀態向量只有 5 家 × 5 年 × 約 40 個數字，
引擎搬進瀏覽器不到 150 行 → `make_web.py` 可內嵌進 `site/index.html`
（tokens.css 已經是這樣內嵌的），GitHub Pages 上的成果頁本身就能玩。

### 11.2 視圖 A：定位空間 —— 選軸即選圖

**核心互動：選幾根軸，就決定畫什麼圖。** 不需要選圖表類型、不需要分頁。

```
1 根  →  排序點圖(dot plot)    五家排在一條數線上,數值直接標
                              ★ 這格最重要 —— 它就是「表格」,是真正讀數字的地方
2 根  →  象限散佈             十字中線 + 四角標籤(報告 §3 那個手畫象限)
3 根  →  3D 散佈,可旋轉
```

**規則（全部定死，不留待決）**

| # | 規則 | 為什麼 |
|---|---|---|
| 1 | **最多三根**，點第四根時**最早選的自動退出（FIFO）** | 只用位置一種編碼;不做「第四根當大小」——面積在感知排序裡接近墊底,五個泡泡讀不出差異。且 FIFO 對「軸以後會變多」是穩的,大小編碼會崩 |
| 2 | 退出的 chip 淡出、新的淡入，軸標籤做換軸動畫 | 不能是死點擊,要看得見是哪根被換掉 |
| 3 | x/y/z 照**點選順序**，可拖曳交換 | 象限四角標籤跟著換 |
| 4 | **顏色永遠是銀行**（BANK_COLORS） | 顏色不能拿去編碼第四根軸 |
| 5 | **報酬軸方向相反**（越大越好），軸線用不同顏色 + `↑好` 標記 | 三根風險軸是「越大越危險」,混搭時象限意義會翻 |
| 6 | 空狀態顯示四根軸的 sparkline 分布，點哪根展開 | 比空白畫面好,順手當選單 |
| 7 | 轉場 300~400ms：`1→2` 點掉到新 y、`2→3` 平面繞 y 軸旋開 | 硬切會斷線;換軸時要看得見誰跑去哪 |
| 8 | **口徑三態鈕**（§11.4a）決定每家畫幾個點：整體/揭露 各一個點，變化 = 兩個點連起來 | 切換不是換兩張圖,是讓銀行從「一個點」變成「一段位移」 |

**時間**

```
時鐘統一「年底」,5 期(2021~2025) —— 理由見 §11.3 的報酬軸
1 軸 / 2 軸   預設顯示軌跡(5 家 × 5 期 = 25 點,連成 5 條線),最新一期加粗
3 軸          預設單期 + 時間播放鈕
★ 口徑=「變化」時**軌跡自動關掉** —— 25 個點各長一支箭頭會糊成一團,只留單期
```

### 11.2a 口徑三態在各種軸組合下長什麼樣

**規則就一條：整體 / 揭露 各是一組座標，「變化」把兩組同時畫出來連起來。**

```
選 1 根(①或②)    整體/揭露 → 排序點圖(原樣)
                  變化      → 啞鈴圖:每家兩點一棒,棒長 = 會計配置的效果
                             軸② 2025:國泰 −5.88━━━−2.16 最長,兆豐 −3.20━−3.76 幾乎沒棒

選 2 根(①②)      整體/揭露 → 象限散佈(原樣)
                  變化      → 箭頭:從「揭露」指到「整體」
                             富邦 2025 (57.1,+0.17) ↘ (80.3,−3.34) 最長
                             兆豐     (75.7,−3.76) ↔ (74.4,−3.20) 短到看不見

混選(如 ①+③)     ③ 不隨口徑動 → 兩點的 ③ 座標相同 → 箭頭是水平的
                  這不用特別寫,自然就是這樣

都沒選到①②      兩點重疊、箭頭長度 0 → **三態鈕灰掉**,不然按了畫面不動會被當成壞了
```

**為什麼預設不做成兩張圖來回按**：純 toggle 的差異要靠記憶比對，看不出誰動最多。
位移長度本身就是「會計配置做了多少事」，是可以直接排序的量 —— 應該畫出來，不是記出來。
**3 軸不畫軌跡**：25 點加 5 條曲線在三維裡互相遮擋，旋轉也救不回來。

> **為什麼一定要有時間**：5 個點在 3D 裡轉一轉就能轉出任何模式。
> 加上軌跡才有結構——玉山那條線一路往右上爬（AC 佔比 11%→40%、殖利率連四年第一），
> 兆豐幾乎原地不動。**那是報告最重要的敘事，只有軌跡圖看得見。**
> 也順便救了軸 3：它的變異幾乎全在時間上（2021 跨行極差 3.0x、2025 只剩 1.3x）。

**參考**：這個互動模型就是 **Tableau 的核心**（學術源頭 Stolte/Tang/Hanrahan 的 Polaris/VizQL）
——「視圖由你選的欄位決定」。軌跡的做法來自 **GapMinder**（Rosling）。
兩個都是被驗證過的方向，不是新奇玩法。

### 11.3 四根軸（定案）

| 軸 | 定義 | 可切換的單位 | 資料 | 等級 |
|---|---|---|---|---|
| **① 信用風險** | 非公債佔比 `1 − ΣP(c,GB) / ΣΣP(c,k)` | — | `data.json` | 【測】零假設，一行可算 |
| **② 利率敏感度** | 「升息 100bp，債券部位跌多少」 | ★ **台幣 / 美元 二選一** | `data.json` + 利率序列 | 【測】+ 線性假設 |
| **③ 槓桿** | `RWA / CET1`（風險加權槓桿倍數） | 可切 `暴險總額/第一類`（真槓桿）、`RWA/暴險`（密度） | `capital.json` + 第三支柱(§7.0b) | 【恆】是 CET1% 的倒數 |
| **④ 報酬** | 證券報酬率，分母 = 平均(AC+OCI) | ★ **三層可勾**（見下） | `capital.json.interest` / `.pnl` | 【測】20/20 驗收 |

**★ 整體 / 揭露：只有 ①② 有兩個位置（定案 2026-08-06）**

同一家銀行有兩個位置 —— **印出來的**（進權益、進 CET1、看得見）與**實際的**（全部）。
兩者的差就是會計分類做的事，這是模擬器唯一想量的東西。

| 軸 | 揭露端 | 整體端 | 機制 |
|---|---|---|---|
| **① 信用** | OCI 桶的非公債佔比 | 全部位（AC+OCI+Trading）的非公債佔比 | **部位面**：信用風險放進哪個桶 |
| **② 利率** | OCI 浮虧率（已入權益） | 再加上 AC 的隱藏浮虧 | **價值面**：AC 藏的損失算不算 |
| **③ 槓桿** | — 不切 | | 全行的量，沒有桶的維度 |
| **④ 報酬** | — 不切 | | 分母鎖 AC+OCI；中信/兆豐的附表根本沒有分桶利息 |

⚠️ **①是「東西放哪個桶」、②是「損失認不認」，機制不同**，tooltip 要分開寫，
不能假裝是同一件事。③④ 在切換時座標不動 —— 這是刻意的，不是漏做。

**這個開關不是裝飾 —— 排序真的會翻**（2026-08-06 實測，HEAD 版 `data.json`）：

```
軸② 2025    揭露:富邦 +0.17 > 玉山 −0.54 > 中信 −1.85 > 國泰 −2.16 > 兆豐 −3.76
            整體:玉山 −2.00 > 中信 −2.73 > 兆豐 −3.20 > 富邦 −3.34 > 國泰 −5.88
            富邦從第1掉到第4;國泰從第4掉到最後而且幅度多一倍;兆豐從最後爬到第3

軸① 2025    揭露:玉山 > 兆豐 > 富邦 > 中信 > 國泰
            整體:玉山 > 富邦 > 兆豐 > 國泰 > 中信
```

跨軸一致的訊號：**兆豐兩根軸的位移都最短**（軸①缺口組內 sd 只有 1.2、軸②整體≈揭露），
它根本沒在用會計分類做事；富邦、國泰位移最長。

⚠️ **但「會計配置是穩定的銀行體質」不成立。** 缺口（揭露非公債% − 整體非公債%）的
組間變異只佔 54%（對照 OCI 佔比是 92%，見 [[oci-share-is-a-bank-trait]]）：

```
        2021   2022   2023   2024   2025    組內sd
中信    +24.6  +30.4  +11.0   +2.2   -7.3    15.5
兆豐     -2.1   -0.6   +0.2   +0.2   +1.3     1.2
國泰     +1.5   -9.2  -12.9  -14.4  -17.5     7.3
富邦     -1.5  -11.8   -4.6  -17.6  -23.2     8.9
玉山     -7.4   -3.6   -2.4   +2.5   -3.9     3.6
```

它會漂，而且 2021→2025 四家往同一個方向走（把信用風險移出看得見的桶）。
**這反而是好題材** —— 它不是常數而是軌跡，正好配 §11.2 的軌跡圖。
是重分類還是新買的部位都進 AC，資料分不出來，**先當假設不要當結論**（n=5）。

**② 利率敏感度 —— 為什麼給兩個單位而不是估一個久期**

軸名寫滿：「**對美國利率**的敏感度」／「**對台幣利率**的敏感度」，**不要簡寫成「利率風險」**。
久期估不出來（§7），但「對某一國利率的敏感度」是量得到的。

★ **切換單位時排序會翻，而那個翻轉本身就是證據**：
§7 反算的隱含 Δy（兆豐 5.0pt ≈ 美元、中信 0.88pt ≈ 台幣）預測就是這個結果。
→ **把估不出來的幣別權重，變成一個按下去看得見的現象。** 與帳面/市值同一招。

```
⚠️ 兩個 β 不能相加。台美利率高度連動,各自的單因子回歸都會吸收對方一部分,
   相加會重複計算。它們是兩個視角,不是一個分解。
⚠️ 要先釘死是哪一條利率。2022 聯邦資金 +425bp、美國 10Y 約 +240bp,差 1.8 倍。
   部位是 5~10 年就該用 10Y。這個選擇進頂部選單,可切。
```

估法：Δ浮虧率 對 ΔUS10Y（或 ΔTW10Y）單因子回歸。
⚠️ **訂正 2026-08-06**：原本想用半年（9 個變動點）估，**做不到** —— `data.json`
的 `wide_cost`（取得成本）只有年報有，H1 那些鍵存在但值全是 `null`。
實際只有 5 個年底觀測 → **4 個變動點**，年頻。`corr(ΔUS,ΔTW)=0.946(n=4)`。
雙因子（同時放兩國、係數比＝幣別權重）留在 §5 當研究，**不上軸**：
軸要穩定，不能補一期資料五家位置就跳。

**③ 槓桿 —— 兩個必須知道的性質**

1. **它是 CET1% 的倒數**，單調變換不是新變數。方向一致（大＝危險）是好事，
   但拿它去算相關＝拿 CET1% 去算 → 就是 §5.3 的「恆等式改寫不是相關性」。
2. **2025 幾乎沒有變異**：`玉山 8.34 / 中信 8.40 / 富邦 8.28 / 國泰 7.89 / 兆豐 7.06`，
   極差 1.3x；2021 是 `中信 6.68 ~ 玉山 9.69`，極差 3.0x。
   **變異幾乎全在時間上** → 只畫單期這根軸等於白給，必須有軌跡。

**④ 報酬 —— 三層，預設只開第一層**

```
層1  票息        interest.securities                        ← 預設 ✓
層2  +已實現      + pnl.oci_realized + pnl.ac_derecog
層3a +未實現(帳面) + pnl.oci_debt_ovi                        ← OCI 評價,進其他權益
層3b +未實現(市值) + Δ(AC 隱藏浮虧)  ← 從 fair_value 附註算,兆豐口徑不同要標記
```

預設層1：已過 20/20 驗收、報告 §3.5 用的就是它、是「持有這些券每年賺多少」最穩的定義。
**層3a/3b 又是「帳面 vs 市值」那組對立**（3a 只認 OCI 評價，3b 連 AC 隱藏浮虧也算）。
勾到層3，2022 五家全部翻負。**這是專案裡第三次出現同一組對立**，刻意保留。

**分母鎖定平均(AC + OCI)，不開放切換。** 附註自己寫分子排除 Trading，
分子分母必須同一把尺；報告已證明含 Trading 會讓兆豐從最後一名變第一名（§3.5）。
**開放切換＝給人踩已知的坑。**

**三個資料現實（已決定怎麼處理）**

1. **富邦**逐年口徑不同（2021/2022/2025 只揭露 AC 桶）→ **空心點 + tooltip 註明**，
   不留白。留白會被讀成「報酬低」。
2. **中信 2021** 缺期初部位（`data.json` 沒有 2020H2）→ **留白，不補**。不造數。
3. ★ **時鐘降成「年」**：`pnl` 與 `interest` 都來自年報，只有年度數字；
   `data.json` 是半年。**全圖統一年底 5 期，不做內插。**
   副作用是好的：軌跡從 10 點變 5 點，3D 那格不會糊。

### 11.4a 口徑三態鈕 —— 版面最上面那一顆（定案 2026-08-06）

```
┌──────────────────────────────────────────┐
│  口徑   [ 整體 ] [ 揭露 ] [ 變化 ]        │   ← 版面最上面,`.ix-seg` 分段控制
└──────────────────────────────────────────┘
   整體 = 實際的(全部位/全部浮虧)
   揭露 = 印出來的(OCI 桶/已入權益)
   變化 = 兩個同時畫,連起來(啞鈴或箭頭,見 §11.2a)
```

**★ 它跟視圖 B 原本的「帳面 / 市值」是同一個開關**（底層都是「AC 浮虧算不算」），
**合成這一顆，兩個視圖共用**。不合的話畫面上會有兩個長很像的切換，沒人分得出差別。

**灰掉的條件**：選到的軸不含 ①②（例如只選 ③④）→ 兩點重疊，「變化」按了不會動。

### 12.2 鍵值格式（逐檔，實測）

period 欄位格式 **各 section 不同，這是坑**：

# 揭露端把 classes 換成 ("OCI",) 就好,其餘完全一樣
# 驗收(揭露端 2025)：中信 49.95 兆豐 75.69 國泰 46.21 富邦 57.14 玉山 84.57

# 驗收：國泰 2025 應為 63.7%（報告 §11 公式①的例子）

# ── 軸② 利率敏感度：升息100bp跌多少 ──────────────────────────
# ⚠️ 訂正 2026-08-06：這根軸**也要用 HEAD 版**。
#    K 排除了股票與貨幣市場，這本身就是分券種，一樣踩單邊分桶。
#    實證：富邦 2022H2 OCI_資產基礎 wide=0 / cost=82 → 浮虧率 -11.41（真值 -2.15）
#          兆豐 OCI_其他 69 / 3                      → -3.80（真值 -5.60）
#    只有「全欄總額」（含股票、貨幣市場）不受影響，但軸② 用的不是全欄。
P = sum(row.get(f"OCI_{k}",0) or 0 for k in K)        # 公允
Q = sum(Dc["wide_cost"][key].get(f"OCI_{k}",0) or 0 for k in K)   # 成本
浮虧率 = (P - Q) / P
# β 估計：Δ浮虧率(年頻,n=4) 對 ΔUS10Y 或 ΔTW10Y 單因子回歸 —— sim/rates.betas()
#         → 每家一個 β(跌%/100bp) + R²（R² 高多半是 2022 那次升息撐起來的,別當穩健係數）
#         ⚠️ 訂正:原想半年頻 9 點,wide_cost 的 H1 值全是 null,只能年頻 n=4
# 驗收：2022H2 五家 OCI 浮虧率應為 中信-4.14 兆豐-5.60 國泰-8.53 富邦-2.15 玉山-3.96（§6.1）
#
# ── 軸② 的「整體端」：加上 AC 藏起來的浮虧 ★ 2026-08-06 定案 ──────────
# 資料早就在了 —— capital.json 的 fair_value 就是 AC 的公允價值揭露(book/fair 兩欄)
ac  = yields.interest(kind="fair_value", field="fair")[(y, bank)]
loss_ac = (ac["fair"] - ac["book"]) / yields.E          # 億,負值=藏著浮虧

# 定案理由:這樣它還是一個「率」,可以跟揭露端並排比。
# 否決的另一案:分母只用 OCI 部位、把 AC 浮虧當額外負擔疊上去 —— 數字更大更聳動,
# 但那已經不是浮虧率,兩端不可比,象限圖的軸會失去意義。
#
# ⚠️ 分母**不要用文件印的 book**。四家「全帳」的 book 含貨幣市場(國泰有 66% 是存單),
#    拿去跟只有債券的 OCI 浮虧率並列就是兩把尺 —— 國泰 2025 會從 −10.85 稀釋成 −3.67。
#    改成把 AC 浮虧全歸給債券部位,代價是假設「貨幣市場浮虧≈0」。
#    ★ 這個假設**用資料驗過**:OCI 桶的貨幣市場同時有公允與成本,實測五家幾乎全期
#      0.00%,最大 −0.39%(同期債券部分是 −8.53 ~ −2.15)。不是硬掰的。
# ★ 兆豐**不標記**(定案 2026-08-06)。它的 fair_value scope 是「扣貨幣市場」,
#    book 本來就只有債券(實測 894 = AC 券種加總) —— 但上面這個分母把五家都
#    壓到「只有債券」這把尺上,兆豐與其餘四家**算完是同一個口徑**,沒有兩把尺的問題。
#    分子也一樣:scope 差的那塊是貨幣市場,浮虧≈0,金額上進不進來都一樣。
#    口徑一樣就沒問題,不要為了「看起來嚴謹」加一個沒有內容的警示。
# ★ 免費對帳:四家全帳的 book == data.json 的 AC債券 + AC貨幣市場
#    (中信 8867=8867、國泰 6866、富邦 8754 vs 8753、玉山 5221) —— 兩個檔對得起來
# 驗收：2025 整體浮虧率 = 中信 -2.73 兆豐 -3.20 國泰 -5.88 富邦 -3.34 玉山 -2.00
#       玉山 2021 缺 fair_value → 整體端留白,不造數

# ── 軸③ 槓桿：RWA / CET1 ───────────────────────────────────
cap = yields.interest(kind="capital", field="cet1")   # {(年,銀行): rec}
rec = cap[(y, bank)]
軸③ = rec["rwa"] / rec["cet1"]                        # 【恆】= 1/CET1率
# 可切：真槓桿 = 暴險總額/第一類（暴險總額**不在 capital.json**，要第三支柱，§7.0b）
#       RWA密度 = rwa / 暴險總額（同上）
# 驗收：2025 應為 中信8.40 富邦8.28 玉山8.34 國泰7.89（兆豐缺，見 §12.6）

# ── 軸④ 報酬：證券報酬率 ────────────────────────────────────

層1 = t[(y,bank)]["yield"]                            # %
pnl = yields.interest(kind="pnl", field="net_income")[(y,bank)]
層2 = 層1 + (pnl["oci_realized"] + pnl["ac_derecog"]) / yields.E / pos * 100
層3a = 層2 + pnl["oci_debt_ovi"] / yields.E / pos * 100
層3b = 層3a + Δ(AC隱藏浮虧)/pos*100                    # fair_value: fair - book
# 分母 pos = yields.positions() 的平均(前一年,當年)，**鎖定 AC+OCI，不開放切換**
# 驗收：報告 §3.5 那張表 —— 玉山 2025 2.60%、兆豐 2025 1.94%
