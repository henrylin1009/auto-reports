# 一層導覽:四個分頁,拿掉會說謊的那一頁

**一句話**:「個體更多」三塊裡有兩塊接的是 2026-07 凍住、產生器已進 archive 的死檔,
其中兆豐的 AC 比主管線少 6,000 億 —— 那不是「資料不夠完整」,是**同一個網站上兩套資料
互相打架**。這份把它整頁拿掉,順勢把兩層導覽壓成一層四項。

範圍:`make_web.py`(分析頁產出)、`web/appnav.js`(全站導覽)、
`web/workbench.js`(工作台路由)、`core/webdata.py` + `server.py`(數字明細搬家用的取數端點)。

重新確認的 —— 使用者知情並選擇線上只留圖表。

## 現況盤點(2026-08-13 實測)

### ① 「個體更多」三塊,資料源狀態完全不同

| 區塊 | 資料源 | 狀態 |
|---|---|---|
| 估值視角(AOCI / AC隱藏損失 / 利率風險) | `phase0.json` | **死檔**,最後更新 2026-07-15 |
| 獲利(粗估NIM / 資金成本) | `pnl.json` | **死檔**,2026-07-16,永遠印 FY2025 |
| 數字明細(寬表) | `data.json` | **活的**,跟個體報表同一條 |

兩個產生器(`phase0.py` / `extract_pnl.py`)2026-08-11 已搬進
`archive/root_scripts_2026-08-11/`,**現行沒有任何程式會重寫這兩個檔**。
跑 `app.py build --write` 一格都不會變。

**不只是舊,是錯**(前次交叉核對結果,見 `[[page2-stale-sources]]`):

- 兆豐:`phase0.ac_book` = 59 億,`data.json` AC 合計 = 6,098 億,**差 6,000 億以上**
  (phase0 的兆豐走 `archive/extract_megabank` 座標特例,口徑跟主管線不同)
- 兆豐 `ac_fv` 全 `None`、2020–2021 `ac_book` = 0.0 → 它在 AC隱藏損失/利率風險圖上根本不出現
- `ac_hidden` 只有 35/70 格
- 反向風險:phase0 有不少 H1 期的 `ac_book`,而 `data.json` 同期 AC 全 `null` ——
  **估值視角看起來比個體報表「更有資料」**,那不是好事

### ② 線上與本機是兩個世界(這點推翻了「網頁上不是有四頁」的直覺)

CI(`.github/workflows/report.yml:39-41`)只把 **`site/`** 這個目錄發上 Pages:

```
site/
  index.html      ← 線上就這一個網頁
  圖1.png 圖2.png
  銀行債券_完整報表.xlsx
```

`web/`(`sim.html` / `workbench.html` / `v4.html`)**從來沒上線過,而且發不上去** ——
GitHub Pages 是靜態空間不跑 Python,但那兩頁活著要靠 `server.py`:
模擬器每次打 `/api/sim`(`sim/axes.py` 即時算四軸)、資料核對打 `/api/overview`、
`/api/cell`、`/api/fill` 一整排。沒有 server 就是空白頁。

| | 本機(有 server.py) | 線上(Pages) |
|---|---|---|
| 個體報表 / 合併報表 | ✅ | ✅ |
| 模擬器 / 資料核對 | ✅ | ❌ 靜態站跑不動 |

**這個不對稱無解,也不是這次改動造成的。** 這份要做的是讓兩邊各自誠實,
而不是假裝線上有四頁。

### ③ 現在的兩層導覽

| 層 | 在哪 | 項目 |
|---|---|---|
| 一級 | `web/appnav.js:20-24` | 分析 / 模擬器 / 資料 |
| 二級 | `make_web.py:941` `#pagetabs` | 個體報表 / 合併報表 / 個體更多 |

分析頁被工作台用 `<iframe src="/site/index.html">` 掛進來(`workbench.js:138-146`),
兩邊 JS 互相看不到對方 —— 這對這份是**好事**:個體/合併切換只要改 iframe 的 hash
(`site/index.html` 本來就認 `#p2`/`#p3`),不必做跨文件通訊。

### ④ 會被打到的一個既有規則

`appnav.js:61-76` 的 `mark()` 現在靠一條特例判斷高亮:
**「分析只認 `#/analysis` 與空 hash;同一頁的其餘 hash 全歸資料」**。
四項之後 workbench.html 底下會有三個項目(個體/合併/資料核對),這條規則必壞 ——
要改成每一項自己宣告 hash、資料核對當 fallback。

## 設計

### 新導覽(本機)

```
銀行債券投資   個體報表  合併報表  模擬器  資料核對          [狀態列]
```

| 項目 | 去哪 | 備註 |
|---|---|---|
| 個體報表 | `/workbench.html#/analysis` | iframe → `/site/index.html`(半年軸) |
| 合併報表 | `/workbench.html#/consol` | iframe → `/site/index.html#p3`(季度軸) |
| 模擬器 | `/sim.html` | 不動 |
| 資料核對 | `/workbench.html#/matrix` | 只改名;`#/buckets` `#/doc/…` `#/v4` 都算它底下 |

### 線上那份(`site/index.html` 單獨開)

頂端 header 只留 **個體報表 / 合併報表** 兩顆 —— 模擬器與資料核對在那裡不存在,
擺上去按了也沒東西。被 iframe 嵌著時(`.embedded`)**整條 `#pagetabs` 隱藏**,
因為外層 appnav 已經接管了這兩顆。

一句話規則:

> **`#pagetabs` 只在單獨開啟時出現;在殼裡一律由 appnav 負責。**

### 數字明細搬家

新增取數端點,業務邏輯照這個 repo 的鐵律放 `core/webdata.py`,`server.py` 只做路由
(`server.py:10-11` 自己寫著「業務邏輯一律不寫在這裡」):

```
core/webdata.py   wide_table()   → {metrics, periods, banks, book, cost, notes}
server.py         /api/wide      → self._json(webdata.wide_table())
web/workbench.js  資料核對頁尾渲染 + 自己一顆口徑鈕
```

**這不是「一道規則兩個實作」的第五個實例**,理由要寫清楚免得日後誤判:
分析頁那張寬表會**整個刪掉**,全 repo 只剩這一張。
但**口徑說明文字**確實會有兩份(分析頁的圖表口徑 vs 這張表的口徑),
所以 `notes` 由 API 一起吐出來,前端不准自己再寫一份字串。

## 驗收

**V1 線上那份不含任何死檔痕跡**
`grep -E "PH0|PNL|RATE|ac_hidden|aoci" site/index.html` **必須零命中**。
現在會命中一堆 —— 那就是它有效的證據。

**V2 數字明細在新家可用且數字對**
資料核對頁尾看得到寬表;切「取得成本」整表換口徑;
抽任一格與 `data.json` 的 `wide[期別|銀行][指標]` 逐字比對相等。

**V3 導覽四項各自亮對**
逐一點過去:個體/合併/模擬器/資料核對各亮各的;
**再點進 `#/buckets`、`#/doc/…`、`#/v4`,「資料核對」必須維持亮著**
(這是 `mark()` 重寫最容易漏的一條 —— 舊註解說子路由沒亮會讓人以為離開了 app)。

**V4 兩張報表不互相污染**
合併報表的期別選單是季度軸(`2023Q1…2025Q4`)、個體是半年軸(`…H1/H2`);
來回切換三次後兩邊的全域列狀態各自獨立。

**V5 反向控制(這條不准全綠)**
把 `phase0.json` 改壞或直接刪掉 → 重建 → **畫面必須完全不變**。
只要有任何一格變了,就代表沒真的斷開,V1 是恆真閘門。

**V6 線上那份單獨開仍可用**
直接開 `/site/index.html`(不經 workbench):header 有站名、更新時間、
**兩顆**分頁,兩顆都能切;不出現「模擬器/資料核對」這種按了沒反應的項目。

前五項本機實跑(`app.py serve`),V6 另開分頁直接訪 `/site/index.html`。

## 這份**會失去**一個東西(已裁示接受)

線上站台將**沒有任何地方看得到原始數字** —— 只剩三張圖,讀者無法驗證圖是怎麼算出來的。
要對數字得回本機開資料核對。

這是裁示 #3 的必然結果,不是疏漏。**若日後想反悔,成本很低**:
把寬表同時也塞回個體報表頁尾即可(資料源是同一個 `data.json`),
但那時就真的變成同一張表兩個實作了,要一起把口徑鈕收成一份。

## 不做的事

- **不碰資料層。** `data.json`、`build.py`、`facts.db` 一行不動。
- **不動模擬器內容。** 它是通的(`/api/sim` 即時算,無中間落地檔),這份只改它在導覽上的位置。
- **不把模擬器/資料核對想辦法發上線。** 那需要一個會跑 Python 的主機,是另一件事。
- **不重接估值視角。** 若日後要救,`capital.json` 已補得到大半(`fair_value` 24/25 格、
  `pnl` 25/25 格),真正缺的只有 `aoci` 與 NIM 的兩個分母 —— 但那是新的一份計畫。
