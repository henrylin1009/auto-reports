## 一、這個工具是什麼（一句話）

> **把財報 PDF 變成可以看的分析，全程在網頁上操作，運算用你自己的 Claude。**

五家銀行的債券資料**不是交付物**，是內建的示範資料集 —— 它存在的目的是證明
這台機器會動，不是它本身有多完整。

## 三、還缺什麼（四件，其餘都是雜訊）

### 缺 1：兩條管線沒有會合 —— 機器內部的分岔

```
PDF ─┬─ fill.py / fill_auto.py ──→ facts/(58) + decisions/(57) ─┐
     └─ v4/reader.py ─────────────→ v4/raw(34) + v4/ledger(2)  ─┴→ build.py → data.json
```
兩個事實庫、兩個 `ratify`（`core/webdata.ratify` / `v4/ledger.ratify`）、
兩套人審介面（`/api/ratify` / `/api/v4/ratify`）、build 裡兩條讀取路徑
（`rebuild_v3()` / `rebuild_v4()`）。

**每條規則都要做兩次，每一格的命運取決於它走了哪條分支。**
實例：claude 重抽的結果落在 `v4/raw` 就停住，進不了 `facts/`，
所以修好的資料清不掉待辦。這不是意外，是這個結構的必然。

### 缺 2：視覺化跟題目焊死

`make_web.py` 一支 931 行，同時做兩件事：畫通用的格網/時間序列，
以及畫這個專案專屬的分析（AC/OCI 配置、殖利率、US10Y 對照）。
換一個題目（例如「上市公司研發費用」）整支要重寫。

### 缺 3：沒有輸入通道

現在拿新 PDF 的唯一辦法是 `resolve.py` 抓 TWSE。工具版必須能**把 PDF 拖進網頁**。

### 缺 4：沒有安裝路徑

沒有 README 說得清楚怎麼開始（現有那份還在描述 `extract_v2` 那代架構），
沒有一鍵啟動，換題目要手改 `config.py`。

## 四、怎麼給出去

**自備 Claude Code。** 這不是新設計，是現在的架構已經如此：

```
使用者有 Claude Code
   ↓  git clone + 雙擊啟動
本機 server.py 起來,瀏覽器自動開
   ↓  把 PDF 拖進網頁
v4/reader.py 呼叫使用者自己的 `claude -p`
   ↓
規則層分桶/對帳/閘門(純程式,不碰 LLM)
   ↓
網頁儀表板 + 人審介面
```

**沒有 API key、沒有伺服器、沒有費用。** 砍掉 gemini 那條（`core/llm.py`
走 `genai.Client(api_key=...)`）同時解決三件事：去掉幻覺來源、去掉 API key
需求、讓「自備 Claude」變成唯一依賴。

分發形式：**GitHub repo + 一個 Claude Code skill**。`/fill` 已經是 skill 的雛形。

## 五、計劃

### 階段 A：讓機器變成一台（缺 1）

1. **`v4/reader` 的產出直接落進 `facts/`** —— 補上缺的那一段接縫
2. **一個 `ratify`** —— `webdata.ratify` 留（寫 `facts/`、蓋 `_src`、格式檢查照擋）；`v4/ledger.ratify` 退場
3. **`build.py` 砍掉 `rebuild_v4()`** —— 只剩一條讀取路徑
4. **砍掉 gemini**（`core/llm.py` + `fill_auto` 的 gemini 分支）

做完之後：「重抽一份文件」不再是一項工作，只是跑一次抽取器，
待辦、覆蓋率、壞字全都是它的副作用。

### 階段 B：視覺化脫鉤（缺 2）

把 `make_web.py` 切成兩層：

- **通用層**：任何 `config` 都畫得出來 —— 格網、逐桶表、時間序列、缺漏標示、
  每格點下去看得到來源（哪份文件、第幾頁、誰抽的、人有沒有改過）
- **題目層**：這個專案自己的分析（AC/OCI 配置、殖利率、模擬器）
  當成「示範」掛在通用層上

判準很簡單：**把 `config.py` 換成另一個題目，通用層要還畫得出來。**

### 階段 C：能拿來用（缺 3、4）

5. 網頁拖放上傳 PDF
6. 雙擊啟動（`.command` / 一行安裝）
7. README 重寫：這是什麼、怎麼跑、怎麼換題目
8. 換題目走網頁設定，不必改 `config.py`

### 階段 D：出貨

9. 合併到 `main`（線上還是 7/24 的舊資料）
10. 五家銀行當內建示範資料集，附完整出處
11. 死碼清掉（35 個 .py 從任何入口都到不了）、修掉 `test_four_exits`

## 六、明確不做

- **不追 100% 資料準確。** 五家銀行是示範，不是交付物。
  近三年 30 格裡 29 格有資料，這對「證明機器會動」已經綽綽有餘。
- **不做 2018–2019。** 兆豐無檔、玉山全掃描，補了也是殘缺的比較圖。
- **不做保留集測驗。** 46 份雙抽取器逐桶對照（45/45 相同、0 不一致）
  已經是比 3 份抽樣更強的證據。
- **不重寫抽取/分類層。** 那兩層已經是通用的，改它們是製造工作。

---

## 七、順序的理由

A 在最前面不是因為它最有價值，是因為**其他每一項都會被它影響**：
視覺化要讀哪個事實庫、上傳完的 PDF 走哪條抽取、README 要教哪一套流程 ——
分岔沒合，這些問題每個都要回答兩次。
