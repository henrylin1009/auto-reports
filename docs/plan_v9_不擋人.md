# v9:驗證程式不再是閘門,是標記器

**一句話**:抓到什麼就放什麼,程式負責標記哪裡可疑,人在網頁上看著改。

---

## 一、為什麼要改

2026-08-12 的實例(富邦 202402 OCI):

```
check_rowsum   OK  diff 0
check_anchor   OK  diff 0
check_page_ref OK
check_bucket_complete  MISMATCH  「1 列對不到桶:['央行票據']」
→ status RED → 整格不歸檔
```

8 列全部抄對、逐列相加 188,887,320 == 錨,分毫不差。唯一的問題是
`央行票據` 這四個字不在 `buckets.SYN` 裡。結果:

1. 完全正確的資料被丟掉,`facts/` 裡什麼都沒有
2. 畫面顯示 RED,看起來像「資料有問題」
3. 於是重抄 —— **必然撞同一道**,因為失敗點在模型的下游
4. 為此燒掉一次 Claude session 額度,再跑一次 DeepSeek,結果一模一樣

**量過的規模**(36 份 v4/raw,108 格):

| 狀態 | 格數 |
|---|---|
| GREEN | 95 |
| RATIFIED | 1 |
| RED | 12 |

12 格 RED 裡 **9 格**死在 `check_bucket_complete`,而這 9 格只由 **5 個相異詞**造成:

```
期貨交易保證金一自有資金 2   國外定期存單 2   央行票據 1
國外政府債券 1   資產交換 1
```

**9 格被擋,肇因是 5 個字典缺字。** 規矩不多,是處置方式錯了。

### 病灶:閘門擺錯層

架構自己寫著(`plan_v3_2_flow.md` §2.2):

```
rows(事實,存原名) → 判斷 → wide(視圖)
```

`央行票據 7,345,878` 是**事實**,被兩個獨立證人驗過(rowsum diff 0、anchor diff 0)。
「它屬於哪個桶」是**判斷**。現在是判斷層缺一個字,把事實層整格擋掉 ——
所以重跑模型永遠沒用。

### 原本那條規矩不是錯的,是多餘的

`checks.bucket_sum_matches` 擋人的理由寫得很清楚,而且是對的:

> **有列落在桶外一律不合格**,即使等式湊得起來 —— 那筆錢會悄悄從發布數字裡消失

但「悄悄」的前提是**畫面把未歸桶的錢藏起來**。只要那 7,345,878 永遠自己站一行,
錢就沒有消失,它就在眼前,只是還沒歸桶。**危害消失了,閘門就不必存在。**

### 這個模式,同一支函式裡已經有先例

`v4/adapter.py:139` 對「未揭露」(amount=None)的處理:

> **未揭露不是分不到桶。** 舊版把它塞進 `unknown` → 整格判死,但文件印出的
> 合計就是見證人 [...] **留著給人看,不當閘門。**

本計劃的核心就是**讓 `unknown` 比照 `undisclosed` 辦理**。同一支函式、隔 30 行、
同一套理由,不是新發明。

---

## 二、原則

1. **歸檔無條件。** 讀得出來就存,事實層不因判斷層的缺口被擋。
2. **witness 照算,但只標記,不決定歸檔。**
3. **錢永遠看得見。** 未歸桶自己站一行,即使是 0 也顯示。
4. **缺字的待辦永遠不是「重抄」。** 是點一個下拉。
5. **仍然不准猜桶。** 猜錯沒有任何檢查抓得到(`buckets.py` 檔頭),這條不放寬。

---

## 三、關鍵拆解:一道混合的檢查 → 兩道

現在 `bucket_sum_matches` 把兩件事綁在一起,所以其中一件不成立就整組失敗:

| 問的問題 | 改後的地位 |
|---|---|
| **抄寫對不對** — Σ(全部列) == 印出小計 | **仍是硬的**,對不上就是抄錯 |
| **歸桶齊不齊** — unknown 是否為空 | **降成標記**,不擋歸檔、只擋發布 |

⚠️ 注意第一條的 Σ **含未歸桶的列**。等式仍然要成立 ——
`央行票據` 那 734 萬要算進去,只是它進的是「未歸桶」而不是七桶之一。
**抄寫正確性一點都沒有放寬**,放寬的只有歸桶完整性。

## 四、步驟

### S1 網站先長出「未歸桶」那一行 ⚠️ 必須第一個做

**改什麼**:桶合計的輸出加一個 `unbucketed` 欄位(金額 + 列名),網站永遠顯示,
即使是 0。

**為什麼第一個做**:它是取代閘門的**安全網**。先拆閘門再補安全網,中間那段時間
網站會畫出少掉 734 萬的假數字 —— 那正是原本的規矩要防的事。**順序不能反。**

**驗收(必須證明會失敗)**:注入一列桶表不認得的假科目 → 網站那一行必須變成非 0;
把那一行藏掉,測試必須紅。恆真的驗收等於沒有驗收(memory/checks-must-fail)。

---

### S2 `adapter.aggregate` 讓 unknown 比照 undisclosed

**改什麼**:
- `unknown` 不再造成 `ok=False`
- `Aggregated` 照樣帶 `unknown`(已經有這個欄位),但 **`book` 要保留**,
  不再套用「不合格就不准給部分正確的七桶」那條
- 恆等式改成 `Σ已歸桶 + Σ側欄 + Σ未歸桶 == printed_subtotal`
- `checks.bucket_sum_matches` 拆成兩支(或加參數):`sum_matches` 管抄寫、
  `unbucketed_names` 管標記

**要小心的**:`Aggregated` 的 docstring 寫著「`ok=False` 時 `book` 是 None ——
不合格的格不准硬湊一個部分正確的七桶出來」。那條規則本身是對的
(針對的是**抄寫不合格**),但現在 `ok=False` 有兩種原因,要分開:
- 抄寫對不上 → 維持原行為,`book=None`
- 只有 unknown 非空 → `ok=True`,`book` 保留,`unknown` 帶著走

**驗收**:富邦 202402 OCI 必須算出 7 桶 + 未歸桶 7,345,878,且
181,541,442 + 7,345,878 == 188,887,320。

---

### S3 v4 全部歸檔

**改什麼**:
- `v4/witness.py` — `check_bucket_complete` 不再進 `hard_failed`
- `v4/ledger.py:file_green` — 不再只挑 GREEN/RATIFIED,**全部歸檔**;
  分流結果只當標記寫進去
- 狀態字彙從 GREEN/RED 改成「差多少錢」+「幾列未歸桶」

**不動的**:`file_cell()` 的 append-only 保護(人工裁示過的格機器不准覆蓋)、
今天剛修好的 force/classes/快照那三件事,全部維持。

**驗收**:對 `202402_富邦_個體|OCI` 跑一次,`facts/` 必須真的多出這一格,
且那 8 列原名一字不差。

---

### S4 文件頁逐列下拉

**畫面**:

```
富邦 202402 OCI                                    p.40  [看原始頁]

  政府公債                    33,243,101   公債        ●
  央行票據                     7,345,878  [ 選桶 ▾ ]   ○
  其他                         7,418,253   其他        ●
  ─────────────────────────────────────────────────
  已歸桶            181,541,442
  未歸桶              7,345,878
  紙上印的合計      188,887,320
  差額                        0   ✅
```

下拉選了就立刻生效,**不重讀 PDF、不呼叫任何模型**。不選就空著,那列停在
未歸桶,不催。

**寫到哪裡** —— 這點我查過才敢寫:**不要寫 `decisions/`。**
那套 B 階段機制(`core/decision_store.py`、三段狀態機、1,658 筆)雖然活著,
但 `buckets.py` 和 `build.py` **都沒有讀它** —— `build.py` 只對
`_sha("buckets.py", "config.py")` 取雜湊。寫進去不會有任何效果。

改用一個薄的疊加檔 `bucket_rulings.json`:

```json
{"央行票據": {"bucket": "貨幣市場", "at": "...", "why": "選填"}}
```

`buckets.py` 匯入時疊在 `SYN` 之上。**同一個詞在兩邊必須同桶,否則大聲失敗** ——
`SYN` 保留手寫論證的那些(像 `國外機構發行債券→公債` 那段 CUSIP 鑑識),
疊加檔收 UI 點出來的。兩個來源一道規則是這個 repo 反覆長 bug 的形狀
(memory/two-implementations-one-rule),所以衝突必須是 loud failure,不能靜靜地誰贏。

---

### S5(選作,不擋前面)LLM 那側少做事

- **不要再問模型 `check_*` 欄位**。`v4/witness.py:18` 自己寫了「一律不信模型自報的
  status」,富邦那次還證明過模型會對著空白掃描圖填 `"OK"`。收到就丟掉重算,那就別問。
- **允許殘缺**:某列金額看不清 → `amount: null` + note,不要逼模型猜一個數字。

改 prompt 有回歸風險,**改前改後都要對 36 份 raw 量一次**,不能憑感覺。

## 五、假設與待裁示

**分析頁的分母怎麼取** —— 你上一輪沒明講,我照本計劃的原則選了,先寫在這裡:

> **分母含未歸桶,且未歸桶自己是一個看得見的切片。**

理由:跟「錢永遠看得見」同一條原則。分母只算已歸桶的話,各桶佔比會靜靜地
被高估,而且每家未歸桶的量不同,跨行比較會偏。

⚠️ **這會動到你已經跑出來的 AC/OCI 配置結論**(memory/ac-oci-allocation-analysis)。
未歸桶不為零的那幾格,佔比數字會變。要翻成另一種算法的話,改動點集中在
桶合計那一層,不必動事實庫。

## 六、實作結果與**與本計劃的偏離**(2026-08-13)

四步都做完了。**三處偏離原計劃,每一處都是實作時量出來才知道的**:

### ① S1 沒有放寬發布路徑(原計劃說要)

原文寫「`results.build` 改用 `arithmetic_ok`,發布部分七桶 + 未歸桶那一行」。
**收回。** 實測 16 格帶未歸桶的格:

| 未歸桶佔比 | 格數 |
|---|---|
| 100%(七桶全 0) | 8 |
| > 50% | 11 |
| < 10% | 4 |

⚠️ **這組數字改過一次。** 第一次量到的是「20 格、10 格 100%」,那是錯的 ——
當時的 `_tally` 沒有先 `closure.flatten()`,把兩層附註誤判成「明細沒抄到」。
修掉之後 `202504_華南_個體|OCI` 從 100% 掉到 2.0%(見 §六⑤)。結論不變
(仍有 8 格是真的空),但**過程證明了:量測本身要先驗過,才敢拿它下結論**。

那 10 格的 `facts/` 裡根本沒有明細列,只有類別小計列(例:`透過其他綜合損益
按公允價值衡量之債務工具投資` 一列吃掉全部)。放行的話網站會出現 10 格
「公債 0 / 公司債 0 / 金融債 0」—— 正是 `v4/adapter.py` 檔頭記載的
「沒有任何其他檢查抓得到」那個災難。

**改成**:`wide`/`wide_cost` 判準一字不動,未歸桶只進 `verdict`/`audit` 與複核台。
使用者要的「有什麼就放什麼」本來就是在複核台核對,不是改發布站的數字。
等 S3 把明細列真的抄進 `facts/`、剩下的是小額餘數時再談放寬。

### ② S3 的 `file_green` 維持只收 GREEN/RATIFIED(原計劃說「全部歸檔」)

**S2 做完之後 RED 的意思變了。** 現在 `check_bucket_complete` 判 RED 只剩
「列相加 != 印出小計」這一種,實測剩下的 3 格分別差 60~125 萬 —— 那是真的抄錯,
不是缺字。把真的抄錯的資料歸檔進 `facts/` 不是「不擋人」,是把錯的當對的存。

缺字的格現在是 GREEN,`file_green` 自然就收了 —— **原本的目的已經達成,不必再
放寬一次**。

### ③ 不做 `bucket_rulings.json`(原計劃 S4 的核心)

查到 `webdata.confirm_bucket()` **已經在做這件事,而且做得更好**:寫進
`buckets.SYN` 原始碼、帶理由與日期的註解、本 process 立即生效、還會自動解套
`work/blocked/` 裡因為那個名字卡住的格。`/api/dispose` 就是它的端點。

用它就沒有「兩個來源一道規則」的問題了 —— SYN 仍然是唯一的桶對照表。
**S4 因此只剩前端**:未歸桶的列顯示「選桶 ▾」,點了走既有端點。

### ④ 新增:`Aggregated.arithmetic_ok`(計劃沒寫,但非加不可)

S2 一度把 `aggregate().ok` 本身改成寬鬆版,結果 `test_v4_to_facts` 當場破 6 格 ——
`aggregate().ok` 與 `wide.View.ok` 對同一份資料給出相反答案。**一道規則兩個實作**
又長出來了。改成兩邊都有 `ok`(嚴格)+ `arithmetic_ok`(寬鬆)、同名同義,
放寬的是**呼叫端怎麼用**,不是定義本身。

### ⑤ 找出並修掉一個「看起來像抓不到頁」的假象(計劃沒預見)

使用者回報 `202504_華南_個體|OCI` 顯示「2 列、全部未收錄、100% 未歸桶」,
問「找不到對的頁數要怎麼解」。**查下去發現根本沒有找不到** —— 三份 record
全都在,是**兩層附註**:

```
p39 母表   權益工具投資 38,409,224 / 債務工具投資 335,458,816   printed_total = 373,868,040 = 錨
p39 子附註 上市櫃股票 26,000,119 + 未上市櫃 7,557,866 + REIT 4,851,239 = 38,409,224  ← 正好是母表第 1 列
p40 子附註 政府公債 149,203,868 + 公司債 96,641,687 + … = 335,458,816              ← 正好是母表第 2 列
```

`core/closure.flatten()` 本來就是為這個寫的,而 `results.build()` / `core/reconcile`
都會先攤平。**漏的是本次新加的 `_tally`**(它直接 `wide.cell(recs)`)。
修掉之後:未歸桶 373,868,040(100%)→ **7,341,572(2.0%)**,已歸桶 366,526,468
分佈在 5 個桶。

⚠️ 連帶修掉一個**本次新引入的危險**:母表那 2 列原本也顯示「選桶 ▾」,
點下去會把「債務工具投資」這種**彙總標題**寫成全域 `buckets.SYN` 規則,
而它的明細已經被攤平算進去 —— 同一筆錢會算兩次,而且六道檢查抓不到。
現在這種列標「彙總列」、不給選桶,判準借 `closure.Tree.is_leaf()`,
**不另寫一套「這列是不是彙總」的猜測**。

| | 之前 | 之後 |
|---|---|---|
| GREEN | 95 | **99** |
| RED | 12 | **8**(3 抄寫錯 + 5 口徑無從判定) |
| 帶「未歸桶」標記但可歸檔 | 0 | **6** |
| 發布數字 | — | **一個都沒變** |

`202402_富邦_個體|OCI` 由 RED 轉 GREEN,witness 從 `MISMATCH` 變成
`UNBUCKETED · 7,345,878 · ['央行票據']` —— 錢看得見,格子不再被擋。

⚠️ **但那一格目前寫不進去**:它已經被人工裁示過(帶 `_src`),`file_cell()` 的

8 列明細取代現在的 2 列粗粒度版本,得先由人 `revoke()`。**這是使用者的決定,
不是機器的。**

## 七、不做什麼

- **不動 `decisions/` 那套 B 階段機制。** 它沒接上 v4 也沒接上 build,
  這次不去修它,也不假裝在用它。(S4 改走 `confirm_bucket` 之後更不需要碰它。)
- **不自動剝「國內/國外/央行」前綴。** 5 個缺字裡有 3 個是「限定詞+既有名詞」,
  很想寫一條規則 —— 別。`國外機構發行債券→公債` 是查了 CUSIP 券號才敢下的判斷,
  不是字面推的。自動剝前綴正好踩進「猜錯了沒有任何檢查抓得到」。
- **不讓 LLM 決定桶。** 提案可以由 `rules.propose()` 給(它會附上命中的
  BUCKET_RULES 關鍵字),人點確認。
- **不放寬抄寫正確性。** 見 §三。
